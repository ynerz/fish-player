## 1. 一句话定位

一款**轻量、挂机友好、收集驱动**的钓鱼游戏。玩家从村口小池塘起步，
靠"收集本钓场图鉴"逐级解锁更深、更怪、更值钱的水域，最终抵达隐藏的 **星陨之渊** 与 **时之尽头**。

平台路线：**纯 Web 单机版 → 微信小程序 / Steam**。

## 1.5 市场调研：主流钓鱼游戏的鱼种规模

做鱼种数量决策前先查了市面上头部产品（2026-10 数据）：

| 游戏 | 鱼种数 | 钓场/水域数 | 类型 |
|---|---|---|---|
| **欢乐钓鱼大师**（国内最火手游，2024 公测） | **300+ ~ 500+**（不同渠道口径不一） | 20+ | 3D 休闲手游 |
| **钓鱼发烧友**（Com2uS） | **200+**（真实鱼类） | 4 大区域 | 拟真手游 |
| **Fishing Planet** | **178+** | 24 | 硬核模拟（PC/主机） |
| **Russian Fishing 4** | **110 ~ 154** | 15~16 张地图 | 超硬核模拟 |
| **Call of the Wild: The Angler** | 12（上线时） | 1 | 3D 开放世界 |

**结论：**
1. 休闲向钓鱼手游的标配是 **200~500 种**，硬核模拟类在 **110~180 种**。
2. 我们最初只有 112 种，**偏低**。
3. **更关键的是**：鱼种数量直接决定「长时长」能不能做出来。
   数学上，一个钓场要让玩家玩几百小时，只有两条路 ——
   **要么鱼极少但个别鱼稀到 1/25000（彩票鱼），要么鱼很多、每条概率都正常。**
   后者才是健康设计。
4. 所以本轮把鱼种扩到 **362 种**（D16 / C24 / B34 / A46 / S62 / SS80 / SSS100），
   同时把最稀有的鱼从 1/25000 拉回 1/9188 以内。

## 2. 核心循环

```
抛竿 ──▶ 等待咬钩（8 秒 ~ 10 分钟，由鱼的稀有度决定）
          │
          ▼
       咬钩窗口（1.2 ~ 1.6 秒，必须提竿）
          │
          ▼
       张力拉扯博弈（7 秒 ~ 40 秒，按住收线 / 松开放线 / 躲逃窜）
          │
          ▼
       结算 ──▶ 金币 + 图鉴登记 + 可能解锁新钓场
          │
          └──▶ 回到底部，继续抛竿
```

一竿的渔获在**抛竿瞬间就已经决定**（只是不告诉玩家），所以"等待时长"和"最终钓到什么"
是同一份随机结果的两个侧面 —— 大鱼就是要等更久，这是刻意的。

## 3. 钓场系统

### 3.1 七个钓场（5 显性 + 2 隐藏）

| 等级 | 名称 | 鱼种 | 解锁条件 | **解锁预计累计** | 本场收满 |
|---|---|---|---|---|---|
| D | 村口小池塘 | 16 | 开局即开放 | — | ~2 h |
| C | 溪流浅滩 | 24 | D 图鉴 80% | **~2 h** | ~4 h |
| B | 湖心半岛 | 34 | C 图鉴 80% | **~6 h** | ~16 h |
| A | 深海断崖 | 46 | B 图鉴 80% | **~22 h** | ~45 h |
| S | 幽蓝海沟 | 62 | A 图鉴 80% | **~67 h** | ~100 h |
| SS | 星陨之渊 | 80 | D~S 全部 100% | **~166 h** | ~132 h |
| SSS | 时之尽头 | 100 | D~SS 全部 100% | **~298 h** | ~529 h |

**全部 7 个钓场 100% 收满 ≈ 828 小时。** 共 **362 种鱼**。

### 3.1.5 关于咬口倍率 biteMul

同一个「普通」稀有度，在村口池塘 8~22 秒就咬钩，在时之尽头要等 28~77 秒。
每个钓场有一个 `biteMul`（D 1.0 / C 1.0 / B 1.2 / A 1.6 / S 2.2 / SS 3.0 / SSS 3.5），
**只作用于普通与稀有档** —— 史诗/传说本来就接近 10 分钟上限，再乘就超出策划设定的单竿时长上限了。

这条倍率是「让后期钓场自然变长」的关键手段之一：不靠把鱼调稀有，靠深水本来就要等更久。

### 3.2 解锁规则（代码实现）

- **显性钓场（C / B / A / S）**：本钓场图鉴收集达到 **80%** 即解锁下一个。
  - D 有 16 种鱼 → 需 13 种；C 有 24 种 → 需 20 种；以此类推（`ceil(n × 0.8)`）。
- **隐藏钓场（SS / SSS）**：前面**所有**钓场图鉴 **100% 收满**。
  - SS 需要 D~S 全 100%（共 182 种）；SSS 需要 D~SS 全 100%（共 262 种）。
- 已解锁的钓场**可以随时回去**补图鉴。

## 4. 鱼的状态：品种 × 颜色 × 重量

每条鱼由三个维度共同定义，共 **362 种品种**。

| 维度 | 内容 | 说明 |
|---|---|---|
| **品种** | 362 种（16 / 24 / 34 / 46 / 62 / 80 / 100） | 决定外形、稀有度、基础价、体重区间 |
| **颜色** | 5 档变异 × 稀有度分档 | 普通鱼 原色 76% / 亮色 10% / 白化 10% / 黄金 3% / 闪光 1%；**鱼越稀有出稀有颜色概率越高**（传说 原色 43% / 亮色 20% / 白化 20% / 黄金 12% / 闪光 5%）。售价系数 1.0 ~ 4.0（**闪光最稀有也最贵**） |
| **重量** | 每种鱼独立区间 | 偏小值分布（指数 2.1），另有 3% 概率出「巨物」（体重 ×1.55） |

**售价公式**

```
售价 = 鱼种基础价 × clamp(实际重量 / 该鱼种中位重量, 0.40, 2.60)
                   × 颜色系数
                   × (首次钓到该鱼种 ? 3.0 : 1.0)      ← 图鉴奖励
```

> 图鉴一旦登记**永久保留**，卖出鱼不影响收集进度。

### 4.0 颜色不参与解锁

**解锁只看「品种」。** 颜色和重量都不参与任何解锁判定。
图鉴里每条鱼下方有 5 个小圆点标出各颜色的收集状态，页首有「颜色 X / 1810」的总进度 —— 这是纯粹的收集彩蛋。
颜色概率**按鱼的稀有度分档**（`config.js` 的 `colorMorphs[].probs[4]`），鱼越稀有越容易出好东西。
点开任意一条鱼还能看到它各个颜色的收集数、出现概率与期望竿数（见 `src/ui/panels.js` 的 `renderFishDetail`）。

### 4.3 同一档位内的"追赶鱼"

每个稀有度档位内部用的是**几何递减权重**（`w` 值），越靠后的鱼越难见：

| 档位 | 档内差距（第一条 : 最后一条） |
|---|---|
| 普通 | 1 : 1.6 |
| 稀有 | 1 : 2.5 |
| 史诗 | 1 : 3.5 |
| 传说 | 1 : 5.0 |

这条梯度让"每个档位里都有一条难搞的"，是图鉴收集的主要动力来源。
要单独调某一条鱼，直接改 `fish.js` 里它行末的 `w` 值（调小即变稀有）。

## 5. 核心玩法：张力拉扯

### 规则

- 按住（**鼠标左键 / 空格**）→ **收线**：进度上涨，张力上涨
- 松开 → **放线**：进度缓慢回落，张力下降
- 鱼不定时**逃窜**，逃窜期间张力急剧上升；逃窜前 0.55 秒有**预警**
- **张力触顶**并持续 0.45 秒 → **断线**，鱼跑掉
- **张力贴地**（< 6）并持续 1.6 秒 → **松线脱钩**，鱼跑掉
- **进度到 100%** → 成功上岸
- 进度超过 20% 后鱼会**逐渐力竭**（最多减 22% 挣扎强度），保证对局收敛，也更像真实钓鱼

### 实测胜率（各 6 万次对局）

| 稀有度 | 熟练玩家 | 熟练耗时 | 普通玩家 | 耗时 | 主要失败原因 |
|---|---|---|---|---|---|
| 普通 | 100.0% | 7.3 s | 100.0% | 7.2 s | — |
| 稀有 | 99.5% | 22.0 s | 93.8% | 19.9 s | 断线 6.2% |
| 史诗 | 90.3% | 30.6 s | 90.5% | 30.4 s | 断线 8.1% |
| 传说 | 77.4% | 39.0 s | 75.2% | 35.2 s | 断线 24.8% |

> 熟练 = 反应 0.15s、看预警就松手；普通 = 反应 0.32s、节奏更迟钝。
> 数字来自 `node tools/balance.js` ①（已固定随机种子，可复现）。
> **调难度**：改 `config.js` 各稀有度的 `fight.dashPower`（逃窜强度，最敏感的参数），
> 改完跑 `node tools/tune.js` 可以扫描出目标胜率对应的值。

> ⚠️ **输入通道的坑（v0.5.5 修）**：画布上的 `pointerdown` 曾经按钓鱼状态写白名单、
> 漏了 `fight`，而且 `G.Platform.input.up` 的签名写错导致**松手监听根本没绑上** ——
> 只玩鼠标的玩家会「按住不收线 / 松手也不放线」，张力必然拉满断线。
> 现在画布按下直接透传主按钮入口，`up(fn)` 的签名有 `verify.js` 第 ⑫ 节盯着。

### 6.1 鱼饵（消耗品）

蚯蚓永久免费且无限，**保证游戏永远不会因为没饵而卡住**。

**消耗口径（v0.5.7 起）**：抛竿时先扣 1 个，但
**「提前收杆」会把这一竿的饵退回** —— 鱼还没咬钩就收线，等于这一竿没发生。

## 7. 挂机系统

- 自动抛竿 → 自动提竿 → 由 AI 自动驾驶完成拉扯（AI 水平写在 `config.idle.auto`）
- **代价：稀有（稀有/史诗/传说）权重 ×0.95**（对应设定里的「稀有鱼概率下降 5%」）
- 挂机时**不弹结算卡**（避免打断操作），但画面右侧有一条**渔获播报**，
  每一条鱼都会实时滚进来：圆点颜色=颜色变异、边框颜色=稀有度、显示鱼名/重量/金币，
  图鉴新增会标「新」、破纪录标「纪录」。最多保留 9 条。
- 页面关闭期间开着挂机的话，回来会**离线补算**（上限 8 小时），并弹一份收获报告

> **付费定位**：设定里挂机是**月卡**功能。当前单机版**免费开放**，
> 开关在 `config.js` 的 `monetization.idleIsSubscribed`，上线前改为 `true` 即可收口。

## 9. 美术风格（定为低多边形 3D）

**所有鱼都是代码程序化生成，没有任何图片素材。**
当前实现是「同一套几何形状 + `G.FishArt.STYLES` 风格参数」的 2D 矢量化绘制；
**2026-10-07 起画风方向改为「低多边形 3D」**（棱面 + 每面平涂明暗），并支持**图鉴详情页 360° 拖拽查看**。

> ⚠️ **口径**：画风 = **低多边形 3D**。旧的 6 套 2D 候选画风（`flat` / `bold` / `water` / `real` / `neon` / `pixel`）
> **全是开发期候选方案，不是玩家功能** —— 不给玩家任何切换入口，
> 写文档、做功能时都不要当卖点。开发期想看对比：控制台 `G.FishArt.setStyle('bold')`；
> 出图用 `tools/style-preview.html`。
>
> **技术取舍（为什么选它）**：它是候选里唯一同时满足「零图片素材 / 支持 360° / 颜色变异可程序化 /
> 362 条能互相区分」四条的风格。位图类画风（水彩、赛璐璐、像素…）做不到 360°，换色也会糊。
> 落地后本节的 2D 风格表退役，详细口径见 `docs/开发者文档.md` §1.2 / §1.3。

| 风格 | key | 特征 | 状态 |
|---|---|---|---|
| **扁平卡通** | `flat` | 柔渐变 + 极细描边 | **已选定**。清爽易读，多端适配最省事，低端机性能最好 |
| 粗描边卡通 | `bold` | 厚轮廓 + 双色平涂 | 开发期候选（辨识度最高，缩成图鉴小图标也分得清） |
| 水彩柔光 | `water` | 半透明叠色 + 晕染 + 纸纹 | 开发期候选 |
| 写实渐变 | `real` | 多段渐变 + 高光 + 鳞片纹理 | 开发期候选（成本最高） |
| 霓虹剪影 | `neon` | 压暗鱼身 + 发光轮廓 | 开发期候选 |
| 像素风 | `pixel` | 低分辨率 + 硬边放大 | 开发期候选 |

**待用户拍板**：其余 5 套是删除还是保留为内部工具（见第 15 节 F1）。

### 数值工具链（改数值的标准流程，**顺序不能换**）

```bash
python tools/gen-fish.py         # 1. 参与生成的鱼名/体重/价格有变 → 重新生成 fish.js
node tools/solve-drop.js         # 2. 反推掉率并写回 fields.js / fish.js
node tools/fix-rarity-price.js   # 3. 稀有度定价归一化（幂等，第二遍应 0 改动）
node tools/balance.js            # 4. 复核：胜率 / 每小时收益 / 图鉴收集耗时
node tools/verify.js             # 5. 自检 37 节
node tools/gen-collect-time.js   # 6. 出收集耗时表
```

- ⚠️ **没改数值就别跑这条链**。`tools/verify.js` 第 ⑭ 节会断言
  「`fix-rarity-price.js` 干跑是 0 条改动」，所以现在的数值链跑完**不会把工作区改脏**；
  一旦发现它报红，说明 `fish.js` 不在归一化不动点上，应该补跑第 3 步并提交。
- 提交门槛永远是：`node tools/test.js` 全通过 + `node tools/verify.js` 0 警告。
- `tools/build.js` 只是**可选的发布打包**，不在开发流程里（改完刷新浏览器即可）：

```bash
node tools/build.js            # dist/fish-player.html（开发版，含 ?dev 调试面板）
node tools/build.js --release  # 剔除 devtools，断言产物里搜不到 G.Cheat
node tools/build.js --check    # 只跑断言不写盘
```

产物 ≈ **464 KB / 1 个网络请求**（原本 24 个），可以 `file://` 双击直接跑。

## 11. 存档结构

存储在浏览器 `localStorage`（一律经由 `G.Platform.storage`），
键名 `fishplayer.save.v1`（另有 `...v1.bak` 备份）。当前 **SAVE_V = 5**。

> ⚠️ 键名里的 `v1` 是**历史遗留，与 `SAVE_V` 无关** —— 不要跟着版本号改它，
> 否则所有老存档都会读不到。

```
{
  v: 5, coin, playTime, field, unlocked{},
  book:   { fishId: { n, maxKg, colors{key:count}, first } },
  baits{}, baitSel, rods[], rodSel, lines[], lineSel, decors[],

  /* 鱼护 / 水族箱（v2） */
  net[], tank[],                    // [{ f: 鱼种id, kg, c: 颜色key }]
  netCap, tankCap, netEx, tankEx,   // 容量与已扩容次数

  /* 长线目标（v3 / v5） */
  daily,                            // 当日 3 条任务（跨天自动重掷）
  weekly,                           // 本周 2 条周常挑战（v5；按 ISO 周键重掷）
  medals, eco,                      // 纪念币 / 生态值（只能换限定装饰）
  tankSec, tankFrac,                // 水族箱被动收益的结算余量与零头
  medalSeen{}, titleSel, achSeen[], achInit,
  locked[],                         // 隐藏钓场被「发现」的记录

  /* 新手引导（v4） */
  tut: { step, done },

  stats: {
    casts, catches, escapes, snaps, idleCatches, maxKg, maxKgFish, totalValue, days,
    byRar[4], byField{}, byBait{}, byWx{}, byTm{},   // 分维计数，Goals 取数用
    netKept, released, netMax, tankMax,
    streak, maxStreak,
  },
  settings: { sound, volume, ambient, idle },
  lastSeen, createdAt
}
```

- **版本迁移**：`migrate()` 按 `d.v` 分支，缺失字段补默认值、类型错的重建为默认值，
  升级后写回新版本号。老存档（v1 / v2 / v3 / v4）都能直接进游戏
  （v4 → v5 只把 `weekly` 置空，由 `G.Goals.init()` 现生成当周挑战，没有数据要换算）。
- **健壮性**：所有入口做 `isFinite` 兜底（NaN 写进 JSON 会变成 `null`，读回来就永久污染金币）；
  损坏时自动回退 `.bak`；支持**一键导出到剪贴板 + 从剪贴板导入**（导入前做字段白名单校验）。
- **成就系统是纯派生的**（只存 `achSeen` 播报记录），所以改成就条件 / 加成就**不需要存档迁移**。

## 12. 后续路线

### 上微信小程序
- 代码本身零依赖原生 JS，主要工作：`localStorage` → `wx.setStorageSync`、
  `Web Audio` → `wx.createInnerAudioContext`、Canvas API 对齐、接入广告/分享能力。
- 平台相关能力**已经全部收在 `src/core/platform.js`**（存储 / 音频 / 画布 / 系统信息 / 输入 5 组接口），
  上小程序时补一份 `platform.weapp.js` 替换掉它即可，逻辑层一行不用改。
- 输入要注意：小程序**没有空格键**，「长按收线」要换成 `touchstart/touchend`。
- 商业化 5 项在这一步开启。

### 上 Steam
- 用 Tauri 或 Electron 打包同一份代码（`tools/build.js --release` 已能产出单文件）。
- 接入 Steamworks：成就（映射图鉴收集度）、云存档、排行榜（最大重量 / 图鉴完成度）。
- 崩溃上报在这一步接：实现 `G.Track.flush(records)`（当前是空壳，返回 `false`）。

### 待补功能候选
- 鱼饵配方合成
- 限时鱼 / 周常挑战（每日任务已有，中周期目标还缺）
- 排行榜（最大重量 / 图鉴完成度）
- 水族箱的「装饰性」扩展（现在是纯展示 + 被动收益）
- 音频素材化（现在是纯 Web Audio 合成，立体声环境音没有素材做不出来）

## 14. 关于「1000 小时」这个目标的数学说明

你希望 **SSS 解锁后还能玩很久，大约 1000 小时收到 90% 的鱼**。
我把这条要求和其他两条一起验证过，结论是：**三者不能同时成立**。

期望收齐时间 ≈ `2 / (最稀有条鱼的单竿概率) × 单竿耗时`，是数学关系，不是调参能绕开的：

| 目标时长（SSS 收 90%） | 需要那条鱼的概率 | 相当于 |
|---|---|---|
| 30 小时 | 1 / 900 | 完全正常 |
| 100 小时 | 1 / 2,500 | 合理 |
| 250 小时 | 1 / 6,000 | 偏稀有 |
| **500 小时** | **1 / 13,000** | **本作现状** |
| 700 小时 | 1 / 18,000 | 很极端 |
| **1000 小时** | **1 / 26,000** | **彩票，不建议** |

**本作的实际取舍：**
- SSS 解锁：**累计 298 小时** ✅（你的硬要求）
- SSS 收满：**再玩 529 小时**，累计 **828 小时** —— 落在 500h 与 1000h 之间
- 代价：SSS 里最稀有的鱼约 **1/9188**，其他六个钓场都 ≥ 1/2840

**想改成一万小时也很简单**：`tools/solve-drop.js` 里把
`MIN_P.SSS` 从 `0.006`（=1/16700 的反推下限）继续调小、`FIELD_TARGETS.SSS.hours` 调大，
重跑一次会自动重算整套掉率并写回数据文件。

## 14.5 鱼护与水族箱（v0.4.0 新增）

钓到鱼时结算卡给两个出口：**卖出**（换金币）或**收进鱼护**（留下）。

- **鱼护**：初始 30 格，可花金币扩容（30 → 60 → 90 …，价格 2,000 / 10,000 / 50,000 / 250,000）
  鱼护里的鱼可以随时 **卖出 / 放生 / 移进水族箱**
- **水族箱**：初始 6 格，扩容 20,000 / 120,000 / 600,000
  只做展示 —— 会把鱼真实画进水里游泳，是收藏的「陈列柜」
- **挂机自动卖出**：挂机时不弹结算卡，没有玩家做选择，所以统一卖出

> **设计要点：图鉴 ≠ 鱼护。** 图鉴是「你见过什么」（钓到即永久登记），
> 鱼护是「你留下了什么」。这两个概念分开，收集的仪式感才立得住 ——
> 原来的版本鱼一上钩就自动卖掉，玩家对「我钓到了这条鱼」是零感知的。

## 15. 天气与时段（v0.5.0 新增）

给「什么时候钓」加上意义，但**不做硬性门禁** ——
不会出现「这条鱼只有下雨才能钓」这种会卡死图鉴的设计。

- **天气** 每 3~8 分钟变一次，四种按权重抽取（晴 44 / 阴 28 / 雨 20 / 雾 8）
- **时段** 用**游戏内时钟**推进（一天 = 20 分钟真实时间），而不是跟随系统时间 ——
  否则只在晚上玩的人永远看不到白天。晨 / 昼 / 暮 / 夜各占四分之一

| 天气 | 稀有档权重 | 稀有颜色 | 时段 | 稀有档权重 | 稀有颜色 |
|---|---|---|---|---|---|
| 晴 | ×1.00 | ×1.00 | 晨 | ×1.12 | ×1.10 |
| 阴 | ×1.06 | ×1.02 | 昼 | ×1.00 | ×1.00 |
| 雨 | ×1.24 | ×1.08 | 暮 | ×1.14 | ×1.12 |
| 雾 | ×1.12 | ×1.14 | 夜 | **×1.28** | **×1.28** |

- 另外每个鱼种可以带**天气偏好 / 时段偏好**（`fish.js` 的 `wx` / `tm` 字段），
  命中时它在该档内的抽取权重 **×2.2**（只是更容易出，不是唯一解）
- 所以「雨天夜钓」是明显的高光时刻，晴天白天一样能玩
- 顶栏的天气芯片点一下会解释当前状态的加成；稀有加成明显时芯片会变绿

> **对数值工具而言天气是「平均态」**：`balance.js` / `verify.js` / `solve-drop.js`
> 都**不传 env**（倍率全为 1），所以节奏表与掉率表仍然是基线口径。
> 离线补算同样用 `G.Weather.neutral()`。

## 16. 长线目标：每日任务 / 周常挑战 / 成就 / 称号（v0.5.1 新增，v0.5.6 补中层）

828 小时只有「图鉴」一个目标太单薄，所以补成三层：
**短（每日）/ 中（每周）/ 长（成就与图鉴）**。
（最初缺的「中层」在 v0.5.6 由**周常挑战**补上；「限时鱼（某条鱼本周概率 ×5）」
因为会改动掉落概率、影响节奏表，属待拍板项，**未做**。）

**每日任务 · 3 条**
- 种子 = **本地日期 + 已解锁钓场数** → 确定性、不联网、同一天同一套
- 11 类模板：钓 N 条 / 抛竿 N 次 / 钓 N 条稀有 / 钓 N 条史诗 / 收进鱼护 N 条 /
  在某钓场钓 N 条 / 用某鱼饵钓 N 条 / 某天气钓 N 条 / 某时段钓 N 条 /
  累计收入 N 金 / 破自己的重量纪录
- 进度 = 当前累计 − 当天基准（`daily.base`），跨天自动重掷
- 每完成一条得 **1 枚纪念币**（一天最多 3 枚）

**周常挑战 · 2 条（v0.5.6 新增）**
- 和每日任务**同一套引擎**，只是种子换成 **ISO 周键**（`2026-W41`，纯函数
  `G.Goals.weekOf(date)`，周一为一周之始、用「本周四」定年份归属）
- 8 类模板（目标值整体比日常大一号）：本周钓 N 条 / 抛竿 N 次 / 卖出 N 金 /
  钓 N 条稀有以上 / 钓 N 条史诗以上 / 收进鱼护 N 条 / 在某钓场钓 N 条 /
  本周钓到 1 条 N kg 以上
- 每完成一条得 **3 枚纪念币**（`config.goals.weeklyMedals`），周一 0 点刷新
- 存档 `S.weekly`（**SAVE_V 4 → 5**）；老档留 `null`，由 `G.Goals.init()` 现生成
- ⚠️ 进度基准 `base` 是**按 metric 记**的 → 同一张模板表里两条模板不能共用 metric
  （`verify.js` 第 ⑯ 节静态断言）

**成就 · 31 个**（图鉴 / 纪录 / 操作三类）
- **纯派生**：只存 `achSeen`（播报记录），条件全部从存档现有数据算出来
  → 改条件、加成就都**不需要存档迁移**
- ⚠️ 取数必须**单调不减**：用 `stats.netMax / tankMax` 这类**历史峰值**，
  用当前快照会因为卖光而回退，峰值永远抓不到

**称号 · 17 个**（14 个来自成就 + 3 个纪念币里程碑）
- 纯展示，可以在「目标」面板佩戴，显示在顶栏

> **奖励口径（用户已拍板）**：奖励**只有**称号与纪念币；
> 纪念币**没有任何消费出口**，也不许换金币 / 鱼饵 / 装备 / 掉率 ——
> 它只是「坚持登录」的纪念章。周常挑战沿用同一条口径。

## 17. 水族箱被动收益与生态值（v0.5.2 新增）

**水族箱被动收益**（「活鱼租金」）

```
单条产出 = 10 × √(该鱼当前售价 / 200)     金/时
```

- 售价里已经含了稀有度、颜色、重量三个维度 → 越稀有 / 越鲜艳 / 越重自然产得越多
- ⚠️ **开平方是必须的**：线性比例下几条百万级顶级鱼就能让「躺着赚」超过「主动钓」
  （实测顶配满格能到主动收益的 118%），玩法直接废掉。
  开平方把高价位段压平，相当于「大鱼更难养」
- 实测（`balance.js` ⑤）：平均满格产出只占主动收益 **2.6% ~ 3.9%**，
  顶配满格 12.1% ~ 27.4% —— 硬断言「平均 ≤10% / 顶配 ≤100%」
- 总产出还受水族箱格数硬上限约束（6 格起，3 次扩容，共 24 格）
- 离线补算走 `idle.maxCatchUp`（8 小时上限），**刻意不看 `settings.idle`** ——
  那条开关管的是「挂机钓鱼」，水族箱是被动收益，没开挂机也该产
- 结算会保留不足 1 金的零头（`S.tankFrac`），否则小鱼 0.7 金/时会被取整吃光

**放生得生态值**

```
生态值 = 稀有度基础值 × 体重系数 × 颜色系数
```

| 项 | 规则 |
|---|---|
| 稀有度基础值（普/稀/史/传） | 1 / 5 / 20 / 70 |
| 体重系数 | `clamp(实际体重 / 该鱼中位体重, 0.6, 2.0)` |
| 颜色系数 | `0.80 + 0.30 × 颜色的售价系数`（比售价平缓得多：闪光 ×4.00 在这里只 ×2.0，避免刷颜色） |

- 生态值**只能换限定装饰**，买不到金币 / 鱼饵 / 装备 / 掉率
- 装饰 14 件里，限定 6 件 = 生态值 4 件 + 纪念币 2 件 → 收集货币有出口

## 18. 新手引导（v0.5.3 新增）

第一次进游戏只有 HUD，没人告诉玩家「按住收线 / 松手放线 / 躲逃窜」，
所以加了 5 步非阻塞气泡（`config.tutorial.steps`）：

| # | 步骤 | 出现时机 | 学会条件 |
|---|---|---|---|
| 1 | 点按钮抛竿 | idle | 抛出去 |
| 2 | 浮漂沉了马上提竿 | bite | 提竿成功 |
| 3 | **按住**不要松手 | fight | 累计按住 1.0 秒 |
| 4 | 张力碰到黄线就**松手** | fight | 张力回落到安全线以下 |
| 5 | 鱼**发力**时立刻松手 | fight | 躲过一次逃窜 |

- **必须非阻塞**：气泡 `pointer-events:none`（只有「跳过」可点），
  否则会挡住「抛竿」按钮，引导就变成了关卡（`verify.js` 第 ⑩ 节硬断言）
- **必须与钓鱼阶段对得上**（`showWhen`），浮漂没动静就喊「快提竿」会教坏人
- 进度存 `S.tut = { step, done }`（v4 起的字段）；走完永久关闭，设置里可以重看
- **挂机时不推进**；v<4 的老存档直接视为「已看过」

## 19. 错误采集（v0.5.5 新增，空壳）

以前启动期抛一个异常就是**白屏、什么都不留**，玩家只能反馈「打不开」。
现在 `G.Track` 至少能回答「崩在哪一步」：

- 挂 `window.onerror` / `unhandledrejection`（用 `addEventListener`，不覆盖别人的处理器）
- 内存**环形缓冲** 40 条，每条记录带 ctx：版本 / 钓鱼阶段 / 钓场 / 图鉴数 / 金币 / 挂机开关
- **连击合并**：同名同文的连续消息只累加 `n`。
  渲染循环里报错是每帧一次，不合并的话缓冲一眨眼就被刷光
- 采集点：`G.Track.error / warn / event`；开发面板有「导出日志 / 清空日志 / 造一个错误」
- 参数全在 `config.track`；**不碰 `localStorage`、不联网**（`verify.js` 第 ⑮ 节硬断言）
- 记日志自身绝不抛异常（所有入口 `try/catch`，序列化带深度上限防循环引用）
- `flush(records)` 是将来接外部服务的**接入点**，当前明确返回 `false`（还是空壳）
