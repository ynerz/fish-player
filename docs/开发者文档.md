## 1. 技术选型与硬约束

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | 原生 ES5/ES6 JavaScript | **开发期无构建步骤**，改完刷新即可 |
| 打包 | `tools/build.js`（可选） | 只在「发布前自查 / 打单文件包」时跑，**不属于开发流程**，见第 15 章 |
| 渲染 | Canvas 2D + WebGL | 2D 界面 / 场景用 Canvas 2D；3D 图鉴走 WebGL。**两者都是浏览器原生 API，不算依赖**（见 §1.2） |
| 模块 | **全局命名空间 `window.G`** | 见下 |
| 依赖 | **零第三方依赖** | 不引 npm 包 / 框架 / CDN，包体小，小程序不用配 npm 构建。**浏览器原生 API 不算依赖** |
| 素材 | **允许外部文件**（2026-10-07 修订） | ⭐ **质量优先，删除了原来的「零素材」**。图片 / 音频 / 字体 / 模型都可以引入；体积预算见 §1.5 |
| 存档 | `localStorage` | 单机版最简单；小程序端替换为 `wx.setStorageSync` |

### 1.1 为什么不用 ES Module（改动前务必理解）

> ⚠️ **这一节要说清楚一件常被误解的事**：「不用 ES Module」**本身不是目的**，
> 它是「`index.html` 双击能跑」推导出来的**结果**。真正的目的只有一条 ——
> 零摩擦调试与零摩擦分发。写成目的就会让人误以为 ES Module 有害，
> 从而错过它本可以带来的好处。
> **2026-10-07 修订 A**：为 3D 图鉴放行 WebGL —— WebGL 是浏览器原生 API，
> **不是**第三方依赖。
> **2026-10-07 修订 B（重要）**：本节原先还写着「不引外部素材也是从这条派生的」——
> **那条派生关系已废弃**。用户拍板「质量优先」，素材允许外部文件，
> 于是 `file://` 也从「最高优先级」降为「开发期便利措施」。见 §1.5。

`index.html` 必须能被**双击直接打开**（`file://` 协议）。
浏览器在 `file://` 下会以 CORS 策略拦截 `<script type="module">`，页面直接白屏。

所以所有脚本用**传统 `<script src>` 顺序加载**，模块之间通过全局对象 `G` 通信：

```html
<script src="src/data/config.js"></script>   <!-- 定义 G.CONFIG -->
<script src="src/core/loot.js"></script>     <!-- 用 G.CONFIG、G.U -->
<script src="src/main.js"></script>          <!-- 最后启动 -->
```

每个模块的写法固定为：

```js
window.G = window.G || {};
G.XXX = (function () {
  var U = G.U;          // 依赖在 IIFE 顶部取，不要在函数内部每次都取
  ...
  return { /* 对外接口 */ };
})();
```

**加载顺序即依赖顺序**，`index.html` 里脚本标签的位置不能随意调整。

### 1.2 画风方向：低多边形 3D（2026-10-07 定）

**决策**：整体美术风格定为**低多边形 3D**（棱面 + 每面平涂明暗），图鉴详情页提供 **360° 可拖拽查看**。

为什么是它 —— 在 27 个候选画风里，只有它同时满足下面**四条**：

| 条件 | 低多边形 3D | 其余候选（水彩 / 赛璐璐 / 像素 / 剪纸…） |
|---|---|---|
| 不引入图片素材 | ✅ 几何体由代码生成 | ❌ 必须出位图，要破约束 |
| 能 360° 旋转 | ✅ 本来就是几何体 | ❌ 位图转不动 |
| 5 档颜色变异可程序化实现 | ✅ 换基色 + 重算明暗 | ⚠️ 位图换色会糊 / 变脏 |
| 362 条鱼能互相区分 | ✅ 网格参数驱动（沿用体型参数表） | ✅ 但资产量爆炸 |

**落地范围：全 3D** —— 场景里的鱼、鱼护 / 水族箱小图、图鉴详情页走**同一套网格**。
不允许「图鉴用 3D、场景用 2D」：同一个材质在两套渲染路径下观感不同，
玩家会看到同一条鱼在两个页面长得不一样，那是画风一致性事故。

**实施状态 `[计划中]`**：本文档其余章节描述的仍是**当前代码状态**（Canvas 2D + 矢量化绘制，
`STYLES` 6 套 2D 候选画风）。落地时以下三处会变，届时同步修订：

| 模块 | 变化 |
|---|---|
| `src/render/fishart.js` | 由「矢量绘制」改为「**生成三角网格**」；9 个体型参数表与颜色取色逻辑沿用 |
| `src/render/mesh3d.js` | **新增**：投影 + 平涂光照 + 深度排序 |
| `src/core/platform.js` | 增补 3D 上下文创建、指针 / 触摸归一化 |

### 1.3 图鉴详情页的动效口径（传说 / 闪光）

**都能做，而且比位图路线容易得多** —— 程序化网格下，动画就是「每帧重算顶点」，不需要逐帧素材。

| 效果 | 实现 | 位图路线为什么难 |
|---|---|---|
| **传说鱼会动** | 顶点做正弦驱动：尾鳍摆动 + 呼吸缩放 + 身体行进波 | 要逐帧出图，362 条 × 若干帧 = 资产爆炸 |
| **闪光鱼亮闪闪** | 光照里加一个**移动的镜面高光项**（随时间扫过体表）+ 叠加闪烁粒子 | 只能叠一张静态星芒，一转就露馅 |

**性能预算的分配口径（这条同时是设计口径）**：

- **只有传说档（`rar` = 传说）与闪光色（`colorMorphs` 的 `shiny`）开动画**，其余静态
- 图鉴**列表缩略图一律静态**（仍走既有的 `IntersectionObserver` 懒绘制），只有**详情页大图**开动画
- 理由有两层：技术上这是性能预算的合理分配；设计上「**稀有的东西才配动**」本身就是稀有度的表达 ——
  玩家不用看数字就知道这条鱼不一般

### 1.4 低多边形的光照形态与颜色变异口径（2026-10-07 定）

**光照形态：强边缘光 + 不加环境光。**

```
强边缘光（背脊 + 尾鳍） · 无环境补光 · 暗面真正不发光
明暗交界对比拉满 · 深色背景（边缘光只在暗底上读得出来）
```

即「暗面靠边缘光勾轮廓」的形态，不是「影棚柔光打满」的形态。
程序化实现上这反而更省：**不需要环境项，只需要一个光向量 + 一层边缘项**。

**颜色变异的口径（5 档，对应 `config.colorMorphs`）**：

| 档 | 视觉手段 | 要点 |
|---|---|---|
| 原色 | 该鱼自己的配色对（`PALETTES[fid]`） | **不是统一灰色** —— 原色是每条鱼的本色 |
| 彩虹色 | **换色相**：整条彩虹（多色相沿体长渐变） | 售价 ×3.00；**黄金的视觉强度必须压过它**（价格梯度的视觉契约） |
| 白化 | **褪色**（色素缺失）→ 奶白体 + 粉鳍 | 手段 = 去色 |
| 黄金 | **换材质**（哑光 → 金属），亮金、高明度 | 手段 = 换材质，与「加光效」区分开 |
| 闪光 | **加光效**（虹彩 + 移动镜面高光 + 闪烁星点） | 闪烁密度按**体型表面积归一化**（薄体型如水母要单独提高） |

> **为什么强调「三种手段互不重叠」**：白化 = 去色、黄金 = 换材质、闪光 = 加光效。
> 三档必须是三种不同的手段；一旦退化成「同一个颜色深一点浅一点」，
> 玩家就读不出稀有度递进，颜色变异这个系统就白做了。
>
> **跃迁幅度要与售价倍率相称**：×1.00 → ×3.00 → ×3.00 → ×10.00 → ×100.00。
> 视觉上的跳跃幅度要和这串数字对得上，否则玩家会认为「便宜的那档更好看」。

### 1.5 素材政策（2026-10-07 修订：质量优先）

**用户拍板：质量优先，删除原「零素材」约束。** 配套的四条纪律与一处代价：

| 项 | 规定 |
|---|---|
| 允许的素材 | 图片 / 音频 / 字体 / 模型文件 —— **都可以引入** |
| 加载方式 | **一律走统一的资源表 `G.Assets`**，业务代码里不许硬拼路径（便于整体替换与统计体积） |
| **体积预算** | **主包 ≤ 4 MB、资源总量 ≤ 30 MB** —— 不是拍脑袋的数字，是**微信小游戏的硬限制**（主包 4MB / 总包 30MB），我们三个目标平台里有它 |
| 来源可复现 | AI 生成的图必须把生成参数（提示词 / 种子 / 尺寸 / 模型）记进 `tools/`，否则换台机器就重做不出来 |
| 版权边界 | **提示词里不许出现 IP 名**；只描述风格与形态 |

⚠️ **代价（必须理解，不能含糊）**：
Chrome 禁止 `file://` 页面读取本地图片文件（跨源限制）。所以
**「双击就能跑」与「外部素材文件」不可兼得**。
这次选了画质 —— `file://` 从**最高优先级**降为**开发期便利措施**：
小素材内联成 data URI 仍可双击，大素材走本地 http 服务或打包产物。

> **细节方案（含 AI 出图与 360° 旋转的冲突）见 `docs/AI素材方案.md`。**

## 3. 数据流与依赖关系

```
                       ┌──────────────┐
                       │  data/*.js   │  纯静态数据
                       └──────┬───────┘
                              │ 被读取
      ┌───────────────────────┼───────────────────────┐
      ▼                       ▼                       ▼
┌──────────┐           ┌──────────┐           ┌──────────┐
│  Loot    │           │  State   │           │ FishArt  │
│ 抽卡/售价 │◀──调用────│ 存档/图鉴 │           │ 鱼类绘制  │
└────┬─────┘           └────┬─────┘           └────┬─────┘
     │ 被 fishing 调用       │ 被 ui 调用             │ 被 scene/ui 调用
     ▼                      ▼                       ▼
┌──────────┐           ┌──────────┐           ┌──────────┐
│ Fishing  │───启动───▶│  Fight   │           │  Scene   │
│ 主状态机  │           │ 张力拉扯  │           │ 场景渲染  │
└────┬─────┘           └──────────┘           └──────────┘
     │ 回调                        ▲
     ▼                             │ setRodBend / splash / sparkle
┌──────────────────────────────────┴───────────┐
│  main.js  主循环：Fishing.update → Scene.render│
│            → Hud.updateFight → Hud.syncStats  │
└───────────────────────────────────────────────┘
```

**单向依赖**：`data → core → ui/render → main`。
`core` 不直接操作 DOM（除了 `state.js` 读写 localStorage、`audio.js` 用 AudioContext），
所有画面更新都通过 `main.js` 里注册的回调（`onCatch` / `onState` / `onToast`）传出。

这是刻意的：**换成小程序时，只要替换 `main.js` + `ui/` 这一层，`core/` 和 `render/` 基本不用动。**

## 4. 核心系统详解

### 4.1 数据层

#### `config.js` — 全局数值

```
G.CONFIG = {
  version, saveKey, saveKeyBak,
  rarity[4],        // 稀有度：名称/颜色/咬口时长区间/拉扯参数
  fight{...},       // 张力拉扯全局规则（含两个判定窗口：触顶 snapGrace / 贴地 slackGrace）
  storage{...},     // 鱼护 / 水族箱：容量、扩容价格、挂机是否自动卖出
  snap{...},        // 断线修理费比例与保底
  unlockHoursAsGate,// 是否把设计时长当硬解锁门槛
  colorMorphs[5],   // 颜色变异，按「常见→稀有」排列（末项 = 最稀有色）
                    // probs[4] 是**按鱼的稀有度分档**的概率：probs[0]=普通 … probs[3]=传说
                    // ⚠️ 每档 5 个值必须合计 100%；probs[0] 是全体共用基准，不要动
  weight{...},      // 重量分布：skew / 巨物概率
  economy{...},     // 起始金币 / 售价系数 / 首捕奖励
  idle{...},        // 挂机：稀有权重惩罚 / 自动驾驶 AI 参数
  monetization{...},// 商业化预留
  misc{...},        // 咬钩窗口 / 自动保存间隔 / 手感参数（抛竿动画 / 拉扯上限 / 挂机节奏 / 咬口预告）
}
```

#### `fields.js` — 钓场

每个钓场对象的关键字段：

| 字段 | 含义 |
|---|---|
| `rarity[4]` | 四档的**掉落占比**（由 `solve-drop.js` 反推写回） |
| `biteMul` | 咬口倍率，只作用于普通/稀有档（见 §4.2） |
| `requires` / `requireFull` | 解锁前置：单个钓场 80%，或数组全部 100% |
| `estUnlockHours` / `estOwnHours` | 展示用的期望时长（由 `balance.js` 实测） |
| `theme{...}` | 场景主题：天空/水体渐变、地形、环境粒子、暗角 |

> ⚠️ `rarity` 数组会被 `tools/solve-drop.js` **直接改写**，不要当手工数值维护。

#### `fish.js` — 鱼种（自动生成）

由 `tools/gen-fish.py` 生成，362 条。每条记录：

```js
{ id, name, rar,          // 0普 1稀 2史 3传
  shape,                  // fish/eel/ray/squid/jelly/oarfish/shark/whale/dragon
  body, accent,           // 体色 / 辅色
  minKg, maxKg, price,
  w,                      // ★ 档内权重（由 solve-drop.js 写回）
  tail, body_ratio,       // 外形微调
  spiny, barbels, glow, teeth, lure, stripes, spots,   // 外形开关
  field }                 // 所属钓场（由 id 前缀推出）
```

### 4.2 `loot.js` — 抽卡内核

**这是全项目最重要的一个模块**，因为它保证了「游戏实际掉率」和「数值仿真」用的是同一份代码。

```js
G.Loot = {
  rollKg(fish),               // 重量：偏小值分布 + 3% 巨物溢出
  rollColor(rarIdx),          // 颜色：按 colorMorphs.probs[rarIdx] 抽 ★ 必须传鱼的稀有度
  colorProb(cm, rarIdx),      // 取某颜色在某档位的概率
  colorProbTotal(rarIdx),     // 某档位 5 个颜色概率之和（校验 / 归一化用）
  colorByKey(key),
  rarityWeights(field, opts), // 四档权重（叠加鱼饵 / 鱼竿 / 挂机惩罚）
  rollFish(field, opts),      // 抽一条鱼 → { fish, rar }
  biteTime(rar, opts),        // 上鱼等待时长（秒）
  price(fish, kg, color, isNew),
  generate(field, opts),      // 一次完整的「钓上来」结果
};
```

**咬口时长公式**（`biteTime`）：

```
咬口秒数 = rand(该稀有度 timeMin, timeMax)
          × (稀有度 ≤ 1 ? field.biteMul : 1)     ← 只有普通/稀有吃倍率
          × (鱼饵 ? 鱼饵.speed : 1)
```

为什么倍率只作用于普通/稀有：史诗 150~320 秒、传说 380~600 秒本来就贴着策划的
「单竿不超过 10 分钟」上限，再乘 3.5 倍就爆了。而普通鱼占渔获的大头，
拉长它才能有效地、均匀地拉长整场节奏。

**权重公式**（`rarityWeights`）：

```
w[t] = field.rarity[t]
       × (t ≥ 1 ? 鱼饵.rareMul × 鱼竿.rareMul : 1)
       × (t ≥ 1 且挂机 ? idle.rareWeightMul(0.95) : 1)
w[3] 再 × 鱼饵.legendMul
```

然后是 `U.weighted(该档鱼种, 'w')` 在档内按 `w` 抽具体鱼种。
单条鱼的绝对概率 = `field.rarity[t]/Σw × f.w/Σ(档内w)`。

### 4.3 `fishing.js` — 主循环状态机

```
idle ──cast()──▶ flying ──0.85s──▶ waiting ──waitLeft≤0──▶ bite
                                       │                      │
                                  giveUp()               strike() / 窗口超时
                                       │                      │
                                       ▼                      ▼
                                     idle              fight ──▶ resolve ──▶ idle
```

| 状态 | 玩家可做 | 代码入口 |
|---|---|---|
| `idle` | 抛竿 | `Fishing.cast()` |
| `flying` | —（动画 0.85s） | — |
| `waiting` | 提前收杆 | `Fishing.giveUp()` |
| `bite` | 提竿（1.2~1.6s 窗口） | `Fishing.strike()` |
| `fight` | 按住 / 松开 | `Fishing.press()` / `release()` |

**关键设计：渔获在 `cast()` 时就已决定**（`Loot.generate`），
它的 `wait` 字段决定了这一竿要等多久。玩家看到的「等很久 = 大鱼」是真实信息，不是错觉。

挂机模式下，`update()` 里 `case 'idle'` 会自动 `cast()`；
`bite` 状态会自动 `strike()`；`fight` 状态交给 `stepAuto()` 这个自动驾驶 AI
（参数在 `config.idle.auto`）。

**离线补算**：`Fishing.offlineCatchUp(seconds)` 用「期望值折算」而不是逐条模拟，
避免长时间挂后台回来卡死。上限 `config.idle.maxCatchUp`（8 小时）。

### 4.4 `fight.js` — 张力拉扯

每帧根据 `holding` 更新两个量：

```
张力 tension   ← 按住 +tensionRise，松开 −tensionFall，逃窜 +dashPower×力竭系数
进度 progress  ← 按住 +reelPower×鱼竿.reel，松开 −slackPull×力竭系数
```

判定：

| 条件 | 结果 |
|---|---|
| `tension ≥ tensionMax` 持续 `snapGrace`(0.45s) | `snap` 断线 |
| `tension ≤ slackSoft`(6) 持续 `slackGrace`(1.6s) | `escape` 脱钩 |
| `progress ≥ 100` | `success` |
| `elapsed > 300`（兜底） | `escape` |

**力竭机制**（`tire`）：进度过 20% 后，鱼的挣扎强度线性衰减到 78%。
这一条是**保证对局收敛**的关键 —— 没有它，史诗/传说会陷入无限僵持。

逃窜节奏：`nextDash` 倒计时，进入 `dashWarnLead`(0.55s) 时 `warn` 从 0 涨到 1，
UI 据此提示玩家松手。`dashGapMin/Max` 会被鱼的体型系数 `sizeK` 缩放
（`sizeK = 0.88 + 0.42 × 体重在鱼种区间内的分位`），所以同种鱼里的大个体更难拉。

### 4.5 `state.js` — 存档与进度

存档结构见 [`GDD.md` §11](GDD.md)。要点：

- `load()` → `migrate()`：缺失字段自动补默认值，**加字段不用写迁移代码**
- `save(now)`：`now=false` 时只写主档不写备份（高频调用用这个）
- `scheduleSave()`：1.2s 防抖
- **`sellFish(price)` 是「卖鱼入账」的唯一出口**：金币与 `stats.totalValue`
  （成就「累计卖鱼收入」的取数口径）必须一起涨，然后发 `coin` 事件。
  挂机自动卖出、离线补算、结算卡「卖出」全走它。
  ⚠️ 不要在别处手写 `stats.totalValue += p` —— 漏一处成就口径就悄悄偏了，
  而且没有 NaN 兜底；`verify.js` 第 ㉒ 节会扫全部 `src/`。
- **卖鱼 / 卖水族箱走 `credit()` 兜底**：`Loot.price()` 是
  `Math.max(1, Math.round(p))`，而 `Math.max` 遇 `NaN` 仍返回 `NaN` ——
  脏存档（`kg` 是 NaN）能算出一个 NaN 价，裸的 `S.coin += p`
  会把金币**永久**变成 NaN（存档写出去就是 `null`）。
- **图鉴 `book` 只增不减**，卖鱼不影响
- `fieldProgress(fid)` 只统计**品种**，不含颜色 —— 解锁条件的唯一依据
- `colorProgress()` 是纯展示用的收集度统计

## 6. UI 架构

- `hud.js`：只负责**同步显示**和**把输入转成回调**，不含业务逻辑。
  `main.js` 通过 `Hud.init({onPress, onRelease, onIdleToggle})` 注入行为。
- `panels.js`：`VIEWS` 对象是弹层的注册表，`open(name, arg)` 即渲染。
  每个 `VIEWS[x].render(root, arg)` 直接操作 DOM。
  **加了新弹层要同时更新 `hud.js` 里的 tab 按钮和 `VIEWS`。**
- `panels.js` 的图鉴有两个要点，改动时注意：
  - **默认定位当前钓场**：`open('book')` 会把 `bookFilter.field` 重置成 `St.get().field`，
    列表页的钓场筛选顺序是「各钓场 → 全部钓场（最后）」。
    这里刻意把 `open()`（重置筛选）和 `refresh()`（只重绘）拆成了两个函数 ——
    点筛选按钮走 `refresh()`，否则筛选会被自己重置掉。
  - **鱼种详情页**：`bookFilter.sel` 存鱼种 id，非空时 `VIEWS.book.render` 走
    `renderFishDetail()`。单竿概率由 `baseFishProb()` 现算
    （= 档位权重占比 × 该鱼在本档鱼池的权重占比，**不含鱼饵/鱼竿加成**）。
    颜色概率要用 `Loot.colorProb(cm, f.rar)` 按**那条鱼自己的稀有度**取，不要用固定值。
  - **「最稀有已收集颜色」判定**：`colorMorphs` 按常见→稀有排列，所以直接比数组下标，
    不要比概率值（分档之后不存在单一概率）。
- **`refresh()` 是「一个 tick 最多重绘一次」**（排队合并，`refreshTimer` 闸门）：
  一次点击里它常被喊好几遍 —— 点击回调自己一次 + `St` 的 `net` / `eco` 事件各一次
  （放生会连发两个），整面板 DOM 就被重建 2~3 遍。
  ⚠️ 别把 `refresh()` 改回同步 `renderCurrent()`；`verify.js` 第 ㉑ 节盯着。
  但 `open()` **必须**同步渲染（面板刚打开不能先空一帧），并且会取消排队中的那次。
- `devtools.js`：URL 带 `?dev` 或 `#dev` 才挂载，见 §11。

顶栏 / 底栏的 DOM 在 `index.html` 里写死，`hud.js` 用 `U.$()` 取。
改布局要同时动 HTML 和 CSS。

## 8. 数值工具链

**改任何数值的标准流程**（顺序不能变）：

```bash
# ① 改鱼种数据（鱼名/体重/价格/档位）
python tools/gen-fish.py          #  → 重新生成 src/data/fish.js
                                  #    ⚠ 只有真的要动鱼名/体重/生成价格时才跑

# ② 改节奏目标（tools/solve-drop.js 的 FIELD_TARGETS）
node tools/solve-drop.js          #  → 反推掉率，写回 fields.js 的 rarity 与 fish.js 的 w
node tools/solve-drop.js --dry    #     只打印不写回

# ③ 稀有度定价归一化（让「档位越高每小时收益越高」在每个钓场都成立）
node tools/fix-rarity-price.js    #  → 写回 fish.js 的 price
node tools/fix-rarity-price.js --dry   #  只打印不写回

# ④ 复核
node tools/balance.js             #  → 胜率 / 节奏 / 收益 / 图鉴耗时 / 全颜色耗时
node tools/verify.js              #  → 数据自检 37 节（0 警告才算过）
node tools/test.js                #  → 单元测试（有失败时退出码 1；确切条数以它自己的输出为准）
node tools/check-roster.js        #  → 各场鱼种与档位分布

# ⑤ 刷新收集耗时文档
node tools/gen-collect-time.js    #  → docs/收集耗时表.html
```

> ⚠️ **没改数值就别跑这条链**。第 ③ 步曾经**不幂等** ——
> 因为重量系数用 `Math.random` 采样估计，且整数鱼价一次变换到不了不动点，
> 于是「按标准顺序重跑数值链」会莫名改掉 `fish.js` 上百行、把工作区弄脏。
> 现在它固定了随机种子并**迭代到不动点**，跑第二遍必须是 **0 条改动**；
> `verify.js` 第 ⑭ 节会直接干跑一次来断言这一点。看到它报红就补跑第 ③ 步。

### 各工具的职责

| 工具 | 输入 | 输出 |
|---|---|---|
| `gen-fish.py` | 脚本内的鱼种表 | `src/data/fish.js` |
| `solve-drop.js` | `FIELD_TARGETS`（每场目标小时数 + 收集比例） | `fields.js.rarity`、`fish.js.w` |
| `fix-rarity-price.js` | 当前鱼价 + `TARGET = [1, 1.8, 4, 10]` | `fish.js.price`（**幂等**，导出 `dryRun()`/`converge()` 供测试用） |
| `balance.js` | 当前数据 | 胜率 / 节奏 / 收益 / 收集耗时表（**固定随机种子**） |
| `verify.js` | 当前数据 + 源码 | 37 节一致性断言（**固定随机种子**） |
| `test.js` | 当前数据 + 源码 | 单元测试：Loot / Fight / State / 面板真渲染 / 构建纯函数（条数以输出为准） |
| `tune.js` | `config.rarity[].fight.dashPower` 扫描范围 | 各 dashPower 下的胜率曲线 |
| `check-roster.js` | 当前数据 | 各场鱼种数与档位分布 |
| `gen-collect-time.js` | 当前数据 | `docs/收集耗时表.html` |

> **为什么三个工具都固定随机种子**：它们输出的数字会直接抄进 GDD / 说明书。
> 用 `Math.random` 的话每次跑出来的数都略有不同，文档就永远对不上，
> 而 `verify.js` 的警戒线（比如「C 场比 D 场高 15% 以上」）会变成抽奖 ——
> 实测 30 次里有 1 次会误报成警告。门禁必须可复现。

### `solve-drop.js` 的求解模型

- **目标函数**：`E[收齐 top-k] × 单竿期望耗时` 命中 `FIELD_TARGETS[fid].hours`
  - `k = ceil(n × 目标比例)`，SSS 是 0.9（收 90%）
- **精确公式**（不是 `Σ(1/p)`，那是单条鱼的期望）：
  ```
  E[T] = ∫₀^∞ [1 − Π_j (1 − e^(−p_j·t))] dt
  ```
  实现上做归一化 `u = p_min·t` 后 Simpson 数值积分。
- **搜索空间**：三参数 `(R, d2, d3)`
  - `R` = 稀有档总占比，`d2` = 史诗/稀有，`d3` = 传说/稀有
- **设计约束**（缺一个就会解出难看的解）：
  | 约束 | 作用 |
  |---|---|
  | `MIN_COMMON` | 普通档占比下限（不能少到没日常鱼） |
  | `MIN_RARE` | 稀有档占比下限（防止 97% 都是杂鱼） |
  | `MIN_P` | **单条鱼概率的绝对下限（禁止彩票鱼）** |
  | `D2_BAND` / `D3_BAND` | 形状合理性带 |
  | 档位概率严格递减 | 防止「传说比史诗还常见」 |

⚠️ **`Σ(1/p)` 与真实期望的关系**：`E[收齐] ≤ Σ(1/p)`，鱼种概率越均匀差得越多。
用错会全线高估 1.5~2 倍。这个坑踩过两次。

⚠️ **写回百分比至少保留 3 位小数**。传说档常是 0.0x%，
round 到 1 位会放大 10% 以上误差，直接毁掉节奏。

## 9. 开发约定与禁忌

### 必须遵守

1. **不加第三方运行时依赖、不加构建步骤。** 浏览器原生 API（Canvas 2D / WebGL / Web Audio /
   `localStorage`）**不算依赖**，可以直接用。**渲染与游戏逻辑仍然手写** ——
   素材可以外购 / AI 生成，但**引擎不换**（换引擎解决的是渲染器，不是画质本身）。
2. **素材允许外部文件**（2026-10-07 修订：**用户拍板「质量优先」，原「零素材」约束删除**）。
   允许图片 / 音频 / 字体 / 模型。但**四条配套纪律**不能少：
   · 素材一律走统一的资源表 `G.Assets`，**不许在业务代码里硬拼路径**（便于替换与统计体积）
   · **体积预算：主包 ≤ 4 MB、资源总量 ≤ 30 MB**（对齐微信小游戏的硬限制，见 §1.5）
   · 素材来源必须**可复现**：AI 生成的图要把生成参数（提示词 / 种子 / 尺寸 / 模型）记进 `tools/`
   · 不得用 IP 名做提示词（版权边界，见 §1.5）
   ⚠️ **代价说清楚**：Chrome 禁止 `file://` 页面读取本地图片文件（跨源），
   所以「双击就能跑」与「外部素材」**不可兼得**。这次我们选了画质：
   `file://` 从**最高优先级**降级为**开发期便利措施**（小素材内联 data URI 仍可双击，
   大素材走本地 http 服务或打包产物）。
3. **所有平衡数值集中在 `data/`**，逻辑代码里不许写死数值。
4. **抽卡必须走 `G.Loot`** —— 否则 `tools/balance.js` 的仿真失去意义。
5. **`fish.js` 不要手改**，改 `tools/gen-fish.py`。
6. **描边宽度必须走 `LWM()`**。
7. **`core/` 里不要直接操作 DOM**（`state.js` 的 localStorage 与 `audio.js` 除外）。
8. **平台能力一律走 `G.Platform`**：`localStorage` / `AudioContext` /
   `document.createElement('canvas')` / `devicePixelRatio` / 输入事件 /
   `navigator.clipboard` / 原生 `confirm`·`prompt` / `location.reload` / `document.visibilityState` /
   `window.addEventListener` 都不许在业务代码里直接碰，否则上小程序时就要全局搜替换
   （`verify.js` 第 ㊱ 节会扫全部 `src/` 来盯这条）。
9. **画风 = 低多边形 3D**（2026-10-07 定，见 §1.2）。旧的 6 套 2D 候选画风（`STYLES`）
   在 3D 渲染器落地后退役；**玩家侧始终不暴露任何画风切换入口**。
10. **不加新的数值来源**：同一个数值只许有一处定义。
    踩过的坑：张力安全线在 `config.js` 写了一份、CSS 里又硬编码 `width:78%`，
    JS 初始化失败时界面就退回一个错的值，而且不报错
    （现在由 `hud.js` 从 `G.Fight.SAFE` 写行内样式，`verify.js` 第 ⑬ 节盯着）。
11. **工具的输出必须可复现**：`balance.js` / `verify.js` / `fix-rarity-price.js`
    都固定随机种子。门禁或文档数字会拿来用，就不许有随机性
    （实测 `verify.js` 第 ⑧ 节的警戒线 30 次里会误报 1 次）。
12. **写断言后要反向验证**：故意破坏输入，看它是不是真的会报错 ——
    否则不知道断言到底在不在跑。
13. **弹层不许盖住顶栏**：顶栏是面板的导航（`data-panel` 标签页），
    被遮罩盖住就只能「先关一次、再点一次」才能切面板。
    `.modal` 从 `top:var(--hud-h)` 开始，标签页在面板打开时可以就地切换
    （`verify.js` 第 ⑲ 节盯着）。
14. **不留「零消费」的死函数**：`G.U` 里曾躺着 `rnd / irange / pick / chance / normalize`
    五个工具函数，长得像基础设施、实际全项目零调用 —— 读代码的人会以为它们是常用工具。
    加工具前先确认有消费方；没有就直接删。
    `verify.js` 第 ㉕ 节会扫导出面，`test.js` 的 Util 段用白名单把 21 个导出钉住。

### 性能红线

- 主循环里不要做 DOM 查询（`U.$()`），一次性缓存在 `hud.js` 的 `el` 对象里
- **不要在 `render()` 里新建对象**，尤其是 Canvas 渐变：每帧建十几个渐变
  在 60fps 下就是每秒上千个 `CanvasGradient`，低端机 GC 压力明显。
  一律走 `scene.js` 的 `grad('key', make)` 缓存工厂（`resize / setField` 时失效）；
  「颜色随时间呼吸」的那种（灯笼光晕）改成**预渲染离线图 + `globalAlpha`**。
  `verify.js` 第 ⑰ 节会扫源码断言这件事。
  ⚠️ 旧文档在这里写过「渐变每帧重建是可接受的」，是错的 —— 技术债 #16 就是这么留下的
- 不要在 `render()` 里重复 `getContext`（缓存在模块顶部的 `ctx` 里）
- 图鉴一次渲染 362 个条目，用 **`IntersectionObserver`（`rootMargin: 260px`）懒绘制** ——
  只有快滚到眼前的才真画，画完 `unobserve`。
  ⚠️ 早先这里是 `setTimeout(…, 0)` 分批绘制，已经换掉了；别照着旧写法改回去。
  另外实测过：打开图鉴的**首帧 260ms 尖峰是一次性的 JIT / 首次建 DOM 预热**
  （同一个会话里第二次打开只要 1~2ms，打开别的面板同样 ~80ms）
  —— 不是 362 个 canvas 的锅，**不要为此去做虚拟滚动**
- 粒子数量控制在数百量级
- 主循环锁 60fps（`main.js` 的 `FRAME_MIN`），高刷屏不再空转
- **面板里「没有会动的东西就别每帧重绘」**：水族箱动画（`panels.js` 的 `drawTank`）
  在空缸时只做一次尺寸比较就早退 —— 原来缸里一条鱼都没有，
  水 + 亮带 + 沙还每秒整幅重画 60 次。但**不要简单理解成「只画一帧」**：
  画布尺寸是 CSS 撑出来的，窗口缩放后不再重画就会被拉变形，所以是「按需重绘」。
  缸里有鱼时照旧每帧动画。`verify.js` 第 ⑰ 节盯着（早退必须在取 `ctx` 之前）
- **一次交互最多重绘一次面板**：`panels.js` 的 `refresh()` 排队合并，见 §6

## 10. 常见任务怎么做

### 加一条鱼

```python
# tools/gen-fish.py  →  FIELD_FISH['A'] 列表里加一行
 ('新鱼名', 1, 'fish', 0.5, 3.0, 128, 'body:0.42, spiny:true'),
#  名称   稀有度 体型   最小kg 最大kg 价格  外形选项
```

然后：
```bash
python tools/gen-fish.py && node tools/solve-drop.js && node tools/balance.js
```

### 加一个钓场

1. `data/fields.js` 加一个对象（照抄现有结构，改 `id/rank/name/theme/requires`）
2. `tools/gen-fish.py` 的 `FIELD_FISH` 和 `PALETTES` 里加对应 key
3. `tools/solve-drop.js` 的 `FIELD_TARGETS / MIN_COMMON / MIN_RARE / MIN_P` 加一行
4. 跑一遍 §8 的流程
5. `theme` 里的字段含义见 §4.1 的 `fields.js` 表

### 加一套画风

在 `src/render/fishart.js` 的 `STYLES` 里加一项，常用参数：
`lineScale`（线宽倍率）、`lineColorFn(p)`（描边色）、`flatFill`（平涂代替渐变）、
`alpha`、`filter`（CSS filter 字符串）、`glowBoost`、`dark`（压暗鱼身）、`pixel`。
加完打开 `tools/style-preview.html` 就能看到对比。

### 加一种体型模板

`fishart.js` 里加 `TPL.xxx = function (ctx, fish, L, opt, palette, rand) {…}`，
然后在 `fish.js` 的 `shape` 字段里用 `'xxx'`。
模板里画图必须**以原点为中心、朝 +x 为鱼头**，长度按 `L` 缩放。

### 改上鱼节奏

`tools/solve-drop.js` 的 `FIELD_TARGETS`（每场目标小时数、收集比例），
`data/config.js` 的 `rarity[].timeMin/timeMax`（各档咬口区间），
`data/fields.js` 的 `biteMul`（深水倍率）。

| 项 | 现状 | 说明 |

## 13. 移植路线（小程序 / Steam）

### 微信小程序

`core/` 与 `render/` 基本可复用，需要替换的是**平台适配层**：

| 能力 | Web | 小程序 | 涉及文件 |
|---|---|---|---|
| 存储 | `localStorage` | `wx.setStorageSync` | `state.js` |
| 音频 | `AudioContext` | `wx.createInnerAudioContext`（需预生成音频文件） | `audio.js` |
| Canvas | `document.createElement('canvas')` | `wx.createOffscreenCanvas` | `fishart.js` · `panels.js` |
| 事件 | `pointerdown/up` | `touchstart/end` | `hud.js` · `main.js` |
| 布局 | DOM + CSS | 需要在 Canvas 里画 UI，或改用 WXML | `ui/*` |

**最大改动是 UI**：小程序没有 DOM，`panels.js` / `hud.js` 需要重写为
「Canvas 内绘制」或「WXML + WXSS」。建议：

1. 把 `core/` `render/fishart.js` 原样搬过去（它们不碰 DOM）
2. UI 用 WXML 重写一遍（工作量最大但最稳）
3. `audio.js` 改成播放预生成的音频文件（用 `fs` 导出合成的 wav）

### Steam

用 **Tauri** 或 **Electron** 打包同一份 Web 代码，改动最小。
打包前先 `node tools/build.js --release` 得到**单个 HTML 文件**（约 517 KB，
零依赖零素材），把它塞进去即可 —— 不用处理任何相对路径。
需要接入 Steamworks：成就（映射到图鉴完成度）、云存档、排行榜（最大重量 / 图鉴完成度）。

## 15. 单文件发布构建

`tools/build.js` 把 `index.html` + `assets/css/style.css` + `src/` 下的全部脚本
**内联成一个 HTML 文件**（当前 25 个模块 → 约 517 KB）。
（这个数字会随模块变化，`verify.js` 第 ⑪ 节会拿真实构建比对，漂了就报红。）

> ⚠️ 它**不是开发流程的一环**。开发期依然是「零构建」：改完源码直接刷新浏览器，
> 第 1 章「无构建步骤」这条硬约束没有被破坏。这个脚本只在两种时候跑。

```bash
node tools/build.js                  # → dist/fish-player.html（开发版，含 ?dev 调试面板）
node tools/build.js --release        # → dist/fish-player.release.html（剔除 devtools）
node tools/build.js --check          # 只跑断言不写文件（CI / 提交前自查）
node tools/build.js --out out.html   # 指定输出路径
```

`dist/` 在 `.gitignore` 里 —— 产物不入库，避免「源码改了但产物是旧的」这种腐化。

### 15.1 为什么要它

| 用途 | 说明 |
|---|---|
| **发布前自查** | 断言「产物里没有任何指向本地文件的 `src=` / `href=`」，也就是验证**零依赖 / 零素材**这个卖点还成立 |
| **打小体积包** | 上 Steam / 上小程序时，最小移植单位就是这一个文件 |
| **防止发布包混进调试面板** | `--release` 会剔除 `src/ui/devtools.js`（即 `G.Cheat.*`），并断言产物里不含 `G.Cheat` |

### 15.2 内联的正确性依赖什么

1. **所有 `<script src>` 必须连续挨在一块**（`index.html` 里那一整块），
   脚本用「整块替换」的方式内联 —— 中间插了别的东西就会漏掉一部分。
2. **`config.js` 必须第一**（它建 `window.G`）、**`main.js` 必须最后**（它 `boot`）。
   这两条在 `build.js` 里是硬断言，`verify.js` 第 ⑪ 节也会复查。
3. **每个模块正文原样拼接**，只在模块之间插一行独立的 `;` 作分隔 ——
   上一段末尾要是没有分号，直接接下一段的 `(function(){...})()` 会被解析成
   「函数调用」，静默改语义。
4. 拼接**不会**改变作用域语义：所有模块本来就是传统 `<script>`，共享全局作用域。

### 15.3 产物断言（不过就退出码 1）

| 检查 | 为什么 |
|---|---|
| 模块文件都存在、无重复引用 | 拼错路径 = 白屏 |
| `index.html` 里 `<script src>` 是连续整块 | 「整块替换」的前提 |
| `config.js` 第一 / `main.js` 最后 | 加载顺序即依赖顺序 |
| 内联内容里没有 `import` / `export` | ES Module 在 `file://` 下会被 CORS 拦 |
| 内联内容里没有 `</script` | 会提前闭合脚本标签，后面的代码变成页面文字 |
| 产物里没有指向本地文件的 `src=` / `href=` | 零依赖
| 产物里没有外链样式表 | 同上 |
| release 版不含 `G.Cheat` | 调试面板不上线 |
| 产物体积 < 1.5 MB | 超过说明内联进了素材（比如 base64 图） |

### 15.4 自动自检（`verify.js` 第 ⑪ 节）

比上面的产物断言更早一步，`verify.js` 会在**不构建**的情况下检查入口本身：

- `index.html` 的 `<script src>` 清单 **==** `src/` 下**全部** `.js`
  （加了新模块却忘了挂进 `index.html` → 直接报错，而不是运行时白屏）
- 顺序约束同上
- **用 `vm` 沙箱按 `index.html` 的顺序真的把每个模块加载一遍**：
  能抓出「顺序错」（表现为 `TypeError: Cannot read properties of undefined`）
  和「语法错误」。`devtools.js` / `main.js` 在加载时就会碰 `location` / `document`，
  这类浏览器全局的 `ReferenceError` 被视为可预期、只做语法解析。
- 版本号单一来源：`config.js` 的 `version` 必须等于 `docs/改进待办.md` 头部基线

> 纯函数（`collectScripts` / `collectStyles` / `assemble` / `auditBundle` /
> `auditHtml` / `build`）都从 `build.js` 导出，`tools/test.js` 有 30 项断言覆盖它们，
> 包括「拿一段含 `</script>` 的假内容喂进去必须被拦下」这类反向用例。

## 16. 后期新增的 4 个核心模块（v0.5.0 ~ v0.5.6）

### 16.1 `platform.js` — 平台适配层（G.Platform）

**目的**：把「跟运行环境强相关」的能力全部收在一个文件里，
游戏逻辑只调 `G.Platform.*`。上小程序时补一份 `platform.weapp.js` 替换掉它，逻辑层一行不改。

| 组 | 接口 | Web 实现 | 小程序要换成 |
|---|---|---|---|
| storage | `get / set / remove / kind` | `localStorage`（被禁用时自动退回内存） | `wx.getStorageSync` |
| audio | `createContext()` | `new AudioContext()` | `wx.createInnerAudioContext` |
| canvas | `create(w, h)` | `document.createElement('canvas')` | `wx.createOffscreenCanvas` |
| sys | `dpr() / size() / now() / isVisible() / reload() / onResize(fn)` | `devicePixelRatio`（上限 2）/ `innerWidth` / `visibilityState` / `location.reload` | `wx.getSystemInfoSync` / `wx.onWindowResize` |
| input | `down(el, fn) / up(fn) / cancel / leave / key` | `pointerdown / pointerup / keydown` | `touchstart / touchend` |
| clipboard | `write(text)` → `Promise<boolean>` | `navigator.clipboard.writeText` | `wx.setClipboardData` |
| dialog | `confirm(msg)` / `prompt(msg, def)` | `window.confirm` / `window.prompt`（带 try 兜底：拿不到按「取消」算） | `wx.showModal` |

⚠️ **`input.up` 的签名是 `up(fn)`，只有一个参数**（松手可能落在页面任意位置，
所以绑在 `window` 上）。踩过的坑：这里曾写成 `up(el, fn)`，而调用方按 `up(回调)` 传参，
于是真正注册的是 `addEventListener('pointerup', undefined)` ——
**「松手」这个动作永远不会生效**：按住能收线、松开不收线，张力必然拉满断线，而且不报错。
`verify.js` 第 ⑫ 节会断言签名，`test.js` 的 Platform 段会真的触发一次监听看回调有没有被调到。

⚠️ 小程序**没有空格键**，「长按收线」要重做成 `touchstart/touchend`。

### 16.4 `track.js` — 错误采集空壳（G.Track）

**要解决的**：以前启动期抛异常就是**白屏 + 什么都不留**，玩家只能说「打不开」。

- 挂 `window.onerror` / `unhandledrejection`（用 `addEventListener`，
  不覆盖别人的 `onerror`），进**内存环形缓冲**（`CFG.track.buffer` = 40 条）
- 每条带 `ctx`：版本 / 钓鱼阶段 / 钓场 / 图鉴数 / 金币 / 挂机开关 → **「卡在哪一步」**
- **连击合并**：同名同文的连续消息只累加 `n`。
  渲染循环里报错是每帧一次，不合并的话缓冲一眨眼就被刷光
- 采集点 `error / warn / event`；`dump()` 出可粘贴的纯文本；`dumpJson()` 出 JSON
- ⚠️ **记日志自身绝不抛异常**（所有入口 `try/catch`，序列化带深度上限防循环引用）
- **环冲落盘**：走 `G.Platform.storage` 写到 `CFG.track.storageKey`（`fishplayer.track.v1`，
  **独立于存档键、与 `SAVE_V` 无关**）。理由是最该拿到的那条日志恰恰是白屏 ——
  刷新之后内存就没了，玩家又不可能一边看白屏一边开控制台。
  新建的 `error` 记录不受节流限制立刻写；其余按 `persistMinMs`（500ms）节流，
  被节流挡下的那次排一个延迟写（不然「报错后立刻崩」丢的正好是最后几条）；
  单次落盘上限 `persistMaxBytes`，超了从最旧的记录开始丢。
  `init()` 时 `load()` 接回上次会话的日志（标 `prev`，`dump()` 里写「来自上次会话」）；
  `clear()` 连磁盘一起清（否则刷新一次旧日志又冒出来）。脏数据逐字段纠正，不抛异常。
- ⚠️ **只走 `G.Platform.storage`，不出现 `localStorage` 字面量、不联网**（空壳的定义），
  `verify.js` 第 ⑮ 节硬断言；`devtools` 的「日志条数」会标出有多少条来自上次会话
- `flush(records)` 是将来接外部服务的**接入点**，当前明确返回 `false`
- `main.js` 里 `boot()` 被 `safeBoot()` 包起来：启动期崩溃记为「boot 启动失败」后原样抛出

### 17.3 ⛔ 图生图的三条铁律（**2026-10-07 起已弃用，本节留作历史存档**）

> ⚠️ **图生图已不再使用**（用户口径：「统一使用文生图」）。本节保留是为了两件事：
> ① 万一将来要回到图生图，这三条是**实测撞出来的**，别重踩；
> ② 里面那条「挂错编码器 = 5 档全崩成噪点」是本项目最隐蔽的一个 bug，
>    排查方法（源码派发顺序 + safetensors 头部指纹 + 固定参考图只换编码器跑 A/B）值得留着。
> 对应的实现 `tools/gen-morph.py` **已删除**（`verify §33-d` 会阻止它复活）。

1. 🔴 **文本编码器必须是 `qwen3vl_8b_int8_convrot.safetensors`**（和文生图**同一个**）。
   曾经误挂成 `qwen3.5_9b_qwen_image_2.1_pe_i2i.int8_convrot.safetensors` ——
   那是 Qwen-Image-2.1 的**提示词增强器 / 编辑用 PE 模型**，**不是 DiT 的文本编码器**。
   它的 state_dict 里是 `model.language_model.layers.0.linear_attn.in_proj_qkv`
   （**linear_attn = Qwen3.5 线性注意力架构**），会被 `comfy/sd.py` 识别成 `TEModel.QWEN35_9B`；
   而 `sd.py` 的派发顺序里 `QWEN35_*` 分支**排在 `QWEN3VL_*` 前面** → 拿到 `qwen35.tokenizer`，
   **永远进不了** `qwen_image21` 分支。而 `comfy/text_encoders/qwen_image21.py` 里
   `model_type="qwen3vl_8b"` 是**写死**的 → `tokenize(images=...)` 取不到 `qwen3vl_8b` 这一路
   → `image_slots` 永远为空 → DiT 不知道往序列哪个位置拼 `reference_latents`
   → **全零 latent 自由发挥 = 糊状噪点**。
   **症状极其隐蔽**：不报错、尺寸正确、**母版完全正常**，只有 5 档全崩。
   **判别方法**：固定参考图 + 固定 seed，**只换 CLIP 编码器**跑一组 A/B，肉眼看。
2. **`denoise` 必须 = 1.0**。`TextEncodeQwenImage21` 的 latent 输出是
   **`torch.zeros(1,64,H/16,W/16)` —— 一张全零空潜变量**（**不是**「参考图的编码」）。
   参考图是靠 `reference_latents` conditioning **旁路**进 DiT 的。
   所以 `denoise < 1` = 从**全零**开始去噪 → 一片灰糊。
   **想保留更多原图细节要靠 prompt，不是靠降 denoise。**
3. **prompt 必须自带完整风格块**（`BASE` + `LIGHT` + `GEOM` + `BG`）。
   只写「把颜色改成金色」→ 出来是一条**照片级写实金鱼**，低多边形全丢。
   **风格只能靠 prompt 说，不能指望参考图带。**

**工作流结构**（Qwen-Image 2.1 的 i2i，靠 `TextEncodeQwenImage21` 自带的 `images` 输入）：

```
LoadImage → TextEncodeQwenImage21(prompt, images.image_1=[...], vae=...) → 三路输出
            positive / negative / latent(空)
KSampler(latent_image = TextEncode 的第 3 路, denoise=1.0)
```
⚠️ 用的是 `TextEncodeQwenImage21`，**不是** `TextEncodeQwenImageEditPlus`
（`...EditPlus` 是 edit 系模型的节点，配套模型不是本项目的 `qwen_image_2.1_int8_convrot`）。
⚠️ API 里 `images` 的键名是**点号扁平名** `images.image_1`；
写成 `{"images": {"image_1": [...]}}` 这种嵌套字典会被**静默丢弃**，
症状是 latent 退化成 `resolution or 1024` 的**方图**、参考图完全不进模型。
出处：`comfy_extras/nodes_qwen.py::TextEncodeQwenImage21.execute`。

#### 颜色句为什么不能用 §7.2 的 v8 原句（这条**在 t2i 下依然成立**）

> 📌 起因是图生图（i2i 会**锚住参考图的色相**：实测 A01 蓝银鱼用 v8 那句
> `vivid bright saturated colours, punchy high-chroma palette, lively`

> 五档一律**显式写出目标色相**。

|---|---|---|
| 原色 | ✅ | 走 `palette_desc()`（该鱼本色 + 明暗层次） |

| 黄金 | ✅ | 明确写了 `metallic gold` |
| 闪光 | ✅ | 明确写了 `sparkling glittering speckles` |

### 17.9 抠图：成品改为**透明 PNG**（2026-10-07，取代「统一暗底再抠」）

**口径变更**：

| | 做法 | 结果 |
|---|---|---|
| 旧 | 生成时统一暗底，指望后处理抠图 | ⛔ **图生图 `denoise=1.0` 会把整张画布重画**，暗底必然长出云斑（背景 σ 从母版 3.8 涨到 7.7，肉眼可见） |
| 新 | **生成时直接产出真 alpha 的 RGBA** | ✅ 没有背景，就没有背景噪点 |

**⛔ 不能在提示词里写「透明背景」**（用户提过这个思路，原理上不成立）：
扩散模型输出的是**像素**，没有「文件格式」这个概念。写 `standard PNG transparent format`
不会产出 alpha，只会让模型**画出一个棋盘格**（那是它见过的「透明」的视觉表达）。
alpha 只能由**一个专门的分割模型**给出。

**接线**（`tools/cutout.py`，照抄官方蓝图 `Remove Background (BiRefNet).json`）：

```
LoadImage ─┬──────────────────────────────────────────────┐
           │                                              ▼
           └─► RemoveBackground ─► MASK ─► InvertMask ─► JoinImageWithAlpha ─► SaveImage(RGBA)
                  ▲
LoadBackgroundRemovalModel(birefnet.safetensors)
```

🔴 **极性必须反转**：`RemoveBackground` 的 MASK 是**亮 = 背景**，而 alpha 要的是**亮 = 主体**。
少 `InvertMask` **不报错**，只会得到「鱼透明、底不透明」，而且看着还挺「干净」，肉眼极难发现。
→ `verify §33-d` 静态盯住这条接线。

**模型**：`birefnet.safetensors`（423 MiB）放 `ComfyUI/models/background_removal/`
（本项目实际路径是 `D:\Comfy-Desktop\ComfyUI-Shared\models\`，**不是实例目录**）。
下载地址见 `cutout.py` 文件头 —— ⚠️ **HF 直连不通，走 `hf-mirror.com`**，
且仓库路径含子目录（`.../resolve/main/background_removal/birefnet.safetensors`，
少一层会 404）。

**产物口径**：

| 文件 | 内容 | 说明 |
|---|---|---|
| `<id>.png` | RGB 暗底母版 | 留作**「暗底标准外观」存档**：与 `docs/images/标准/` 同口径，也是 `check-cards.py` 的验收入口 |
| `<id>-normal.png` | RGBA 透明 | = **母版的抠图**，不单独生成（省一次出图 + 与母版必然同色） |
| `<id>-bright/albino/golden/shiny.png` | RGBA 透明 | 生成时一并抠好 |

> 📌 **2026-10-07 更新（五档改全文生图之后）**：母版**不再是任何东西的参考图**。
> 旧口径下它必须保持 RGB，是因为图生图要拿它当参考（RGBA 参考图会被
> `TextEncodeQwenImage21` 按**白底**合成 `rgb*a+(1-a)`，成品背景会从深灰漂成全白）。
> 现在没有图生图了，保留母版纯粹是为了**留一份暗底标准外观 + 给 `check-cards.py` 一个入口**，
> 而且**成本为零**（原色档 = 母版抠图，不额外出图）。
> **如果将来不需要暗底版了，可以只保留五档，出图总数不变。**

**实测**：每张 1.5~3 秒（含模型加载），相对 40~55 秒的出图可以忽略；
alpha 基本二值（77% 全透明 / 21% 实心 254 / 0.2% 软边）；
白鱼在**饱和彩底**上无灰边（`docs/images/card-ab/_final2-col-A03-albino.png`）。

**顺手否掉的一条路（留个反例，别重走）**：先试过「泛水填充把背景压成纯色」的确定性后处理，
`bg_sd` 能做到 0.00，看着很完美。但 **暗色鱼的体色和暗底在颜色上无法区分** ——
实测 A03 的鱼背是深灰 (45,45,48)，与背景基准 (30,28,29) 的曼哈顿距离只有 51，
而背景噪点也能跑到同样距离 → 泛水**顺着背鳍与身体之间的缝隙漏进鱼背**，
一口气刷掉约 2 万像素。加几何隔离（腐蚀切断细颈 + 只留最大块）能治住，
但既然真 alpha 更干净也更省事，这个工具已删除（`tools/flatten-bg.py`，2026-10-07）。
**教训：当两个区域在特征空间上重叠时，别在特征空间里找分界线 —— 换一个信息源。**

### 17.10 低模精细度：`GEOM` 曾经写反过（2026-10-07 修正）

**症状（用户原话）**：「每个鱼身上的方块还是太少了，复杂程度不够，感觉没有 v9 版本的骨架那么精细。」

**根因在提示词里，不在模型里。** `GEOM` 原稿：

```
Built from large flat angular facets, clearly visible polygon edges, minimal surface detail, no texture.
```

字面上就是**在命令模型「用大面片、尽量少表面细节」**。这块是 v10 才加的
（v9 没有），目的是防止 `low poly 3D render` 被模型理解成「低模风格的写实渲染」。
但它**过度纠偏**了，把密度一起掐掉了。

🔑 **关键认识：这块防的是「写实」，不是「密度」—— 两者可以同时要。**

| 要防的 | 由谁负责 |
|---|---|
| 写实（细密鳞片 / 柔和渐变 / 照片感） | `flat shading per facet` / `no texture` / `no gradients` / `NEG` |
| 密度（面片要小而多） | `dense triangular polygon mesh` / `many small facets` |

**量化判据（别只靠眼睛说「感觉块面少了」）**：`python tools/facet-count.py`
—— 鱼身剪影内「独立亮度色块」数 ÷ 千像素。

| 版本 | 密度 | 结论 |
|---|---|---|
| v9 标准图 `docs/images/标准/fish_normal.jpg` | **3.56** | 靶子 |
| 老稿（`large` / `minimal`） | ≈ 1.5 | 太粗 |
| 只写 `hundreds of small facets` | 5.65 | 过头，块面发碎、丢可读性 |
| **现稿**（下表） | **3.30** | ✅ 最贴靶子 |

**现稿（`gen-art.py`，骨架常量全项目只此一份 —— `verify §33-e` 会拦住第二份）**：

```
Finely faceted low-poly surface, a dense triangular polygon mesh covering the body,
crisp visible polygon edges, flat shading per facet with subtle tone variation
between neighbouring facets, no texture, no gradients.
```

> ⚠️ 那句 `subtle tone variation between neighbouring facets` 是**让网格「读得出来」的关键** ——
> v9 标准图之所以像低模网格，靠的就是相邻面片之间那点明暗差；只要求「密集平涂」
> 会得到一片没有结构的碎块（这正是候选 A 的失败方式）。

> ⚠️ 调这一块必须**做 A/B 对拍**（同一张鱼、同一 seed、只换 GEOM），
> 并用 `facet-count.py` 记数。只改一版就下结论，等于没测。

### 17.11 真实特征的批量抓取（`tools/fetch-traits.py`，2026-10-07）

**目的**：把 362 条鱼的真实形态描述抓下来，喂给 `fish-traits.json`（§17.5 的 ① 级来源）。
**抓取必须与归一化分开**：「抓」能脚本化，「把中文形态描述归一化成英文标准字段」要判断力
—— 所以本脚本**只抓取 + 缓存**（`tools/.traits-cache/<id>.json`，已 gitignore），归一化另做。

#### 🔴 数据源实测表（**这张表是本节的正文**，省得再撞一遍）

| 源 | 可达 | 形态质量 | 限流阈值 |
|---|---|---|---|
| 快懂百科 `baike.com/wiki/<名>` | ✅ | **最高**（有专门「形态特征」段） | ~**15~20 次**后「验证码中间页」，冷却 **>5 min** |
| 搜狗百科 `baike.sogou.com/Search.e?sp=S<名>` | ✅ | 中高（**搜索结果页的头条摘要就含形态句**） | ~**4 次**后弹验证码 |
| 百度百科 `baike.baidu.com/item/<名>` | ❌ **永久 403** | — | 补完整浏览器头 + Referer 也无效 |
| 中文维基 `zh.wikipedia.org` / `wikiwand` | ❌ 全部超时 | — | — |
| 中国大百科 / 物种2000 / 自然标本馆 | ❌ 404 / 超时 | — | — |
| Bing 搜索 `cn.bing.com/search?q=` | ✅ 不限流 | **低**（摘要以食用/钓鱼/知乎为主） | 未见 |

推论：**单源必死**，架构必须是「**按站轮询 + 每站独立冷却 + 越封越久 + 断点续跑**」。

#### 🔑 四条方法学教训

1. **「免费」的路径是「按名直查词条」，不是「搜索 + 抓候选页」**
   —— 1 次请求 vs 1 次搜索 + N 次抓取；且**标题就是词条名 → 天然精确**。
   实测直查产出率约 **75%**，同一批鱼走搜索只有 **22%**。
2. **虚构物种零误判**：直查时虚构名（星磷鱼 / 虚空鳗 / 无相鲲）**全是 404**，
   不会有「搜到一篇看起来像的科普文」这种假阳性。
3. **限流必须专门识别，不能当成「查不到」**
   —— 否则一次网络抖动/一次封禁就写进缓存，**一个错误变成三重浪费**
   （假失败 → 缓存污染 → 第二遍白跑）。判据：快懂看页 title 是否 `验证码中间页`；
   搜狗看是否含 `SourceVerifyCode` / `id="ip-time-p"`。
   落空记录里带 `partial` 标记 = 「有源当时在冷却」，**不算真落空**，下轮重跑。
4. **「失败得太快」本身就是信号**：曾出现「3 条全失败、每条只花 3 秒」
   —— 根因是 Bing 结果是跳转包装链接被一刀切掉，**候选恒为空、根本没发几次请求**。
   定性：先数请求数，再怀疑内容。

#### 直查的两个副作用（靠校验挡，不靠运气）

| 副作用 | 实例 | 挡法 |
|---|---|---|
| **撞名** | `石斑鱼` → 配音演员「石班瑜」 | 标题校验 |
| **落到近义页** | `鲫鱼` → 「金鱼」条目 | 标题校验 + 摘要含水生词 |
| **异体字误杀**（反向） | `竹荚鱼` 的条目标题写作「日本竹**筴**鱼」→ 互为子串判不出 | 字符重合 ≥ **0.6** |

⚠️ 阈值 0.6 是**卡在实测数据之间**的，别随手改：
`鲫鱼`/`金鱼` = **0.50**、`石斑鱼`/`石班瑜` = **0.33**（都要挡），
`竹荚鱼`/`日本竹筴鱼` = **0.67**（要收）。

⚠️ **必须 `-u`**：不加的话 stdout 被缓冲，重定向到日志后 `wc -l` 恒 0，
**看起来像卡死**，其实在跑。
⚠️ **单条落空可能耗时几十秒**（搜索兜底要发 1 次搜索 + 最多 4 次页面抓取），
`TIMEOUT` 已收到 12s。别用「跑得慢」判断「卡死」，用**缓存文件数**判断。

**解释器**：managed python（只用标准库）。

#### 归一化：`tools/normalize-traits.py`（**抓取与归一化必须分开**）

抓取能全自动，但「把中文形态描述变成英文标准字段」要判断力 —— 逐条手写 100+ 条
不现实，所以做成 **脚本按短语表出草稿 + 人工只审不译**。

```bash
"$PY" tools/normalize-traits.py --draft        # 出草稿 _draft.json（不写特征表）
"$PY" tools/normalize-traits.py --miss         # 打印**没被短语表命中**的中文从句
"$PY" tools/normalize-traits.py --redo --apply # 补完短语表后整体重算并写进特征表
```

四条口径（**都是从踩坑里来的**）：

1. **`markings` 不许出现颜色词**（见 §17.5）。脚本**先摘颜色再进 markings**，
   校验也必须**带词边界** —— 第一版拿 `red` 去查，把 `scatte**red**` 判成了颜色词。
2. **`colour` 存整句中文，不拆字**。拆字得到的是「灰、色、暗、深」这种字符汤；
   整句（「体色青灰带黄，体侧有灰色纵走线」）人才看得懂。反正它不喂提示词。
3. **从句下限是 2 个字，不是 3**。中文形态描述的主干就是「侧扁」「头小」「口端位」
   这类**两字词** —— `体高，侧扁；头小，侧扁` 按逗号切开后全是 2 字。
   第一版设 3，把「鳊鱼」的体型信息整段过滤掉，只剩「口端位」。
4. **短语表里长串必须排在前**（表序即优先级）：「身体无鳞」这条通用规则曾排在
   「颊部裸露无鳞」前面，于是产出 `ctenoid scales, naked skin with no scales`
   这种**自相矛盾**的描述。

⚠️ **宁缺勿猜**：连 `form` 都提不出形态的条目**不进草稿**（比如只有食用/养殖内容的页）。
所以特征表条数 < 抓取命中条数是**正常**的，不是 bug。

⚠️ **`cached_ids()` 必须跳过 `_` 开头的文件**：第一版只过滤 `.json` 后缀，
于是 `_draft.json` 也被算成一条缓存 —— `--report` 的「未抓取」变成 **-1**，
并且在落空分支里取 `d["name"]` 直接 KeyError。**统计脚本自己也会静默算错。**

**结构（两张表，别合并）**：

| 东西 | 位置 | 说明 |
|---|---|---|
| 候选总表 | `gen-art.py:MORPH_CANDIDATES` | 键 = 出处档/编号（`bright/1`…`shiny/5`），值 = (标签, 颜色句)。**20 套全留**——落选句不删，下次换型要原句 |

（A03 黑鲷 × 同种子 × 只换颜色句 = 20 张原始出图 + 4 张带编号/标签/权重的对照表）。

**四条纪律**（都对应踩过或极易踩的坑）：

1. 🔴 **对拍必须「同鱼、同种子、只换颜色句」**。骨架（BASE / LIGHT / GEOM / BG）逐字不变，
   由 `build_morph_prompt()` 保证（`verify §33-c`）。否则「改了哪一句导致变好看」根本无从归因。
   → 所以 `prompt-ab.py` **直接 import `gen-art.py` 复用同一份常量**，绝不在自己文件里再抄一份骨架
   （抄一份 = 又回到「两套骨架各自漂移」的老路，`verify §33-e` 会拦）。
2. 🔴 **颜色句只能有一份**：池子里**只许出现「候选键 + 权重」**，句子原文一律从候选总表取。
   抄进池子 = 两份拷贝，必然漂开（`verify §33-f` 盯住了这条）。
3. 🔴 **抽样必须可复现，所以用 `hashlib.md5` 而不用内置 `hash()`** ——
   后者带 `PYTHONHASHSEED` 随机盐，**每次进程启动结果都不一样**：
   同一条鱼今天出金色、明天出古铜金，**manifest 里的提示词与磁盘上的图对不上**，
   「参数可复现」这条硬约束当场失效。`verify §33-f` 盯住「不许出现 `hash(`」。
4. 🔴 **权重 ≤0 或候选键写错 = 那套句子永远抽不到，而且不报错**（本项目最高频的坑型）。
   所以 `check_pools()` 放在**模块加载时**跑，而不是做成「记得手动跑一下」的工具；
   另外 `prompt-ab.py --picks` 会把每套的实际占比与期望占比并排打出来，
   一眼能看出「有没有死权重」——362 张图没人会去数。

> ⚠️ 这与已删除的 `stable_pick()`（形态随机池）**不是一回事**：
> 形态随机 = 明确的错误（石首鱼科尾鳍是楔形，抽到新月形就是错）；
> 颜色措辞随机 = **同一档位内**的风格差异、色相口径不变，属于「个体差异」，可以做。

**工程坑**：`prompt-ab.py` 出图用 managed python、拼表用 conda python（**只有 conda 有 PIL**）。
PIL 是**延迟导入**的，所以没装 PIL 也只影响 `--sheet-only`，不影响出图。

**manifest 多了 `morphVariant`**：记录每条鱼每一档**实际抽到的标签**。
提示词本身已经能反查是哪一句，但列出标签便于人核对分布与复现。

## 18. 每轮收尾清单（改完必须过一遍）

> **由来**：用户口径（2026-10-07）「每次做完之后整理一下文档，看看有哪些地方修改了需要更改，
> 可以写到规范里面」。
>
> **文档漂移是本项目最贵的隐性成本**：代码改了、文档没改，下一个接手的人照旧口径干活，
> 于是「照着文档做、结果做错」。本清单立起来的当天就抓到 6 处漂移，其中一处
> （「母版保持 RGB：它是图生图的参考图」）会让人**为一个已经不存在的原因**维护一条规则。

**每次改动收尾，按这 5 步走，缺一步不算完成：**

| # | 动作 | 具体做法 |
|---|---|---|
| 1 | 🔴 **找它的「反向陈述」** | 每条改动都问：**哪一句文档在说「它以前是那样」？** 例：i2i 换 t2i → grep `图生图`，逐条判「历史」还是「现行」 |
| 2 | **grep 常量 / 术语 / 文件名** | 改了名字、数值、文件名就 grep 全项目（**含 `tools/` 与 `.html`**）。踩过：删了 `cm.prob` 但 `gen-collect-time.js` 还在读它 |
| 3 | **同步「三处」** | ① `docs/开发者文档.md`（给接手的人看）② `docs/画风与颜色标准.md`（口径唯一来源）③ `docs/GDD.md`（给玩家/策划看）。**三处口径必须一致** |
| 4 | **门禁跟着改，并反向验证** | 改口径就改 `verify.js` 断言；**新增断言必须先证明它会报红**（故意写坏值 → 应报错 → 还原） |
| 5 | **记忆落盘** | `.workbuddy/memory/YYYY-MM-DD.md` 追加当日记录；**「不能记错」的项**写进 `MEMORY.md` |

**⚠️ 第 1 步最容易漏** —— 因为旧口径通常写得**很肯定**（「必须」「不许」「只能」），
看起来一点也不像过期的。判据：**凡是出现「必须 / 不许 / 只能 / 保持」的句子，都问一句「它现在还是吗」。**

**🔴 自指陷阱（踩过 3 次，务必记住）**：`verify §33` 用正则在**全文**里扫
「数字直接接体型二字」的写法。所以**在文档里讨论这条规则本身时，千万不要把那两个字面量原样写出来**
（本节的 18.1 表格第一版就因为这么写而自判红）。要举例就说「把采样数当成代码体型数」。
**同类自指风险的还有**：`§29` 的禁字面清单（`×0.95`、`上限 8 小时`、`图鉴收集达 80%` 等）、
`§33-e` 的 `GEOM` 禁用措辞。**写规范时先想一句：「我把这几个字写出来，会不会被自己抓？」**

**改文档时顺手查这三类高频漂移：**

| 类型 | 本轮实例 |
|---|---|
| **文件名** | `gen-morph.py` 已删除（`verify §33-d` 拦复活）；文档里 5 处引用要清 |
| **数字** | 单鱼耗时 3.6 → 5 分钟；成品总数 1810 → 2172 张；把「采样数」当成代码体型数写进文档 → 被 §33 判红（已改写） |
| **机制名** | `STYLE` → `BASE/GEOM/LIGHT/BG`；i2i → t2i；`亮色` → `彩虹色` |

**验证口径**（收尾必须全部跑过）：
```bash
node tools/test.js       # → 628 项全过
node tools/verify.js     # → 0 警告
```
