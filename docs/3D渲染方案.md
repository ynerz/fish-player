## 1. 目标与范围

**目标**：把鱼从「Canvas 2D 矢量绘制」改成「程序化三角网格 + 逐面平涂」，并在图鉴详情页支持 360° 拖拽。

**范围**：场景里的鱼、鱼护 / 水族箱小图、图鉴详情页**走同一套网格**。
**不允许**「图鉴用 3D、场景用 2D」—— 同一个材质在两套渲染路径下观感不同，
玩家会看到同一条鱼在两个页面长得不一样。

**为什么不上 WebGL**：参考实现证明 **Canvas 2D 手写投影 + 画家算法**在目标面数下完全够用
（实测三条鱼同屏 161~180 fps）。Canvas 2D 兼容性更好（老 WebView / 低端机），
而且不需要处理着色器编译失败的回退路径。**性能不够时再升 WebGL，接口不变。**

## 3. 网格生成（`fishmesh.js`）

### 3.1 生成算法：车削式

```
对 i 从 0..N（沿脊柱的站数）：
  t    = i / N                          // 0 = 吻端，1 = 尾根
  脊柱位置 (sx, sy) = spine(t)
  半高 hy = hh(t) * H                   // H = 体型的高向尺度
  半宽 hz = hw(t) * W                   // W = 体型的宽向尺度
  对 j 从 0..S-1（环上的段数）：
    a  = 2π j / S
    顶点 = (sx, sy + cos(a)*hy, sin(a)*hz)
对 i 从 0..N-1、j 从 0..S-1：
  记 a=vid(i,j) b=vid(i,j+1) c=vid(i+1,j+1) d=vid(i+1,j)
  三角形 [a,b,c] 与 [a,c,d]
两端各补一个「封口点」做三角扇
```

- 输入：`stations`(N)、`segments`(S)、`spine(t)`、`hh(t)`、`hw(t)`、`H`、`W`
- 输出：`{ verts:[{x,y,z,t,b}], tris:[[i,j,k]] }`
  - `verts[].t` = 沿体长归一化位置（0 头 1 尾），**动画要用**
  - `verts[].b` = 该点在环上的 y 分量（-1 底 / +1 背），**两色身体要用**
- 边界：`hh/hw` 允许在两端取到 0（环退化成一个点，三角面面积为 0，不绘制即自然收尖）

### 3.2 现有 9 个体型参数表的映射

`fishart.js` 现有的 `TPL` 已有「体长 / 体高 / 胖瘦 / 鳍位」等参数 ——
**沿用它们驱动 `hh(t)` / `hw(t)`，不要另起一套数值来源**（项目红线：同一个数值只许有一处定义）。

`hh/hw` 与现有参数的关系：`[待定]` —— 实现时先做一条基准鱼，把 `TPL` 的胖瘦档
（现有 27 档 `body_ratio`）映射成 `H` 的缩放，逐档比对截图后再固化映射表。

### 3.3 体型特例

| 体型 | 做法 | 注意 |
|---|---|---|
| fish / shark / eel / dragon / oarfish | 车削式即可 | eel/oarfish 要用更多 `stations`（16+） |
| **鲸 whale** | 车削式，`hh` 偏胖 | — |
| **水母 jelly** | **脊柱沿 y 轴**（伞盖是绕 y 轴的回转体），环在 x-z 平面 | 触手另走「细带」路径（见 3.4） |
| **鱿鱼 squid** | 车削式 + 三角侧鳍 + 触手细带 | — |
| **鳐鱼 ray** | ⚠️ **车削式做不出来**，见 3.5 | — |

### 3.4 附属结构

| 结构 | 几何 | 参数 |
|---|---|---|
| 尾鳍 | 竖直扇形 3 个三角（根 / 上叶尖 / 上内凹 / 下叶尖 / 下内凹） | `caudal` 长度 |
| 背鳍 | 单个三角（前基点 / 顶点 / 后基点） | `dorsal` 高度 |
| 胸鳍 | 左右各一个三角 | 固定 |
| 龙鱼棘背 | 7 个顶点的锯齿带，底边接在背线上 | `ridge` 高度 |
| 长尾鞭（鳐鱼） | 6 段渐细的扁平带（x-z 平面内，±0.02 起） | `whip` 长度 |
| 触手（水母/鱿鱼） | **不进三角网格**，走独立的「细带」绘制路径 | 根数 + 长度 |

> 触手为什么不进主网格：它是细长条，用三角面表示会吃掉大量面数却看不出细节。
> 用屏幕空间细带（每段投影后按投影长度算宽度画四边形）既省面数又更稳。

### 3.5 ⚠️ 已知局限：鳐鱼需要「平面型驱动」的生成器

车削式的横截面是椭圆，**必然做不出鳐鱼那种「后掠翼尖 + 头部凹口」的平面型**
（参考实现里的鳐鱼现在只是个「宽板 + 鞭尾」，是 9 种里最弱的一个）。

**正解**：鳐鱼单独走**平面型驱动**的生成器 —— 先定义俯视平面型（中线 + 左右翼型的多边形），
再按「沿翼展方向的厚度函数」把它挤压出厚度。

`[待定]` 厚度函数的形状，实现时用「俯视 + 侧视」两张参考图对齐后固化。

## 4. 渲染（`mesh3d.js`）

### 4.1 变换与投影

```
绕 y 轴偏航 yaw，再绕 x 轴俯仰 pitch：
  xr  =  x*cos(yaw) + z*sin(yaw)
  zr  = -x*sin(yaw) + z*cos(yaw)
  yr  =  y*cos(pitch) - zr*sin(pitch)
  zr2 =  y*sin(pitch) + zr*cos(pitch)

相机在 (0,0,camZ)，朝 -z 看：
  d  = max(camZ - zr2, 0.35)          // 近平面夹紧，防止除零/翻面
  s  = f / d                          // f = min(W,H) * 1.45
  屏幕 = ( W/2 + xr*s , H/2 - yr*s )

视空间约定：x 右、y 上、z 朝相机。
```

### 4.2 深度排序（画家算法）

每帧算每个三角面**三个顶点的平均 `d`**，按 `d` 降序（远的先画）。
- 复用两块定长缓冲（`order` 索引数组 + `depth` Float32Array），**每帧不新建数组**
- 边界：严格凸的长条物体（细长的鳗）在极端视角下可能排序出错 —— 若出现，改成按三角面重心排序

### 4.3 光照（口径见开发者文档 §1.4：**强边缘光 + 无环境补光**）

```
N  = 三角面法线（视空间，归一化）；**双面**：若 N·toCam < 0 则 N = -N
toCam = normalize( P.x - W/2, -(P.y - H/2), f )      // 注意 y 取负（屏幕 y 向下）
Lkey  = normalize(-0.32, 0.72, 0.42)                 // 主光：上方偏前左
Lrim  = normalize( 0.26, 0.60, -0.78)                // 边缘光：上方偏后

AMB  = 0.09                                          // ★ 环境项压到极低
diff = max(0, N·Hv)                                  // Hv = 主光方向（闪光档随时间转动）
rim  = pow(1 - |N·toCam|, 2.6) * (0.55 + 0.45*max(0, N·Lrim))

基色 = mix(腹部色, 背部色, clamp(0.55 + 0.9*N.y))     // 用 verts[].b 或法线 y 判断上下
明暗 = AMB + diff * 0.62
最终 = 基色 * 明暗 + 边缘光色 * rim * rimK + 镜面项
```

**这两个方向向量写在配置里，不要散在代码里**（项目红线：同类参数要同族）。

### 4.4 抗锯齿接缝（踩过的坑，必读）

Canvas 2D **逐面填充时，相邻三角面之间会露出底色的发丝缝**，看起来像线框。
修法：填充之后**用同一个颜色描一圈**：

```
ctx.fillStyle = col; ctx.fill();
ctx.strokeStyle = col; ctx.lineWidth = 1.2; ctx.lineJoin = 'round'; ctx.stroke();
```

代价是绘制调用翻倍 —— 实测 720 个三角面仍然 161~180 fps，完全付得起。

### 4.5 闪烁星点（闪光色专用）

在背侧顶点里取约 18 个锚点（`verts[].b > 0.25` 且 `t` 在 0.08~0.9），每个锚点一个随机相位与频率。
每帧按 `sin(t*f + 相位)` 决定透明度，用径向渐变画一个高斯光点。

## 5. 颜色变异 → 材质参数

| 档 | 背色 | 腹色 | 边缘光 | rimK | 镜面 | 星点 |
|---|---|---|---|---|---|---|
| 原色 | 冷淡灰蓝 | 亮灰白 | 淡青 | 0.85 | 0 | 无 |
| 亮色 | **该鱼本色提亮提饱和** | 同上更亮 | 同色系 | 0.95 | 0 | 无 |
| 白化 | 灰白 | 近白 | 淡粉 | 0.80 | 0.10 | 无 |
| 黄金 | 深金 | 亮金 | 暖白 | 1.35 | 0.55（低次幂=整块高光） | 无 |
| 闪光 | 冷蓝 | 近白 | 纯白 | 1.55 | 0.90（高次幂=细高光） | **有** |

**三条硬口径**（见开发者文档 §1.4）：

1. **原色 = 每条鱼自己的配色对**（`PALETTES[fid]`），**不是统一灰色**
2. **亮色 = 同色系提亮提饱和，禁止换互补色**；视觉跃迁幅度必须与售价倍率相称
3. **星点密度按体型表面积归一化** —— 薄体型（水母伞盖）要单独提高，否则细看明显比鱼弱

## 6. 交互

| 行为 | 规格 |
|---|---|
| 横拖 | `yaw += Δx * 0.010` |
| 竖拖 | `pitch += Δy * 0.008`，**夹紧到 ±1.35 rad** |
| 松手 | 记录时间戳，**2 秒后**开始缓动回默认视角（缓出曲线，约 900 ms 到位） |
| 默认视角 | **按体型给**：常规鱼 `pitch = 0`（侧视）；**鳐鱼 `pitch = 60°`（俯视）** —— 侧视下鳐只是一条细缝，正面认不出 |

> ⚠️ **角度与弧度不许混用**。参考实现踩过：`defPitch` 按角度写了 `60`，
> 渲染里当弧度用 → 60 弧度 ≈ 197°，水母被从正上方看着，伞盖塌成一个盘。
> **这种错不报错，只出错的结果** —— 统一在配置里存弧度，或在读取处立刻转换并注释单位。

## 7. 动画（只有传说档与闪光色开）

| 效果 | 公式 | 说明 |
|---|---|---|
| 侧向行进波 | `z += sin(t*2.5 - tNorm*3.4) * 0.085 * tNorm^1.7` | `tNorm` = `verts[].t`，尾部幅度大 |
| 呼吸 | `y,z *= 1 + sin(t*1.55) * 0.022` | 体积轻微脉动 |
| 移动高光 | `Hv = normalize(cos(t*1.2)*0.55, 0.72, 0.42)` | 高光带缓慢扫过体表 |
| 星点闪烁 | 每锚点 `sin(t*f + 相位)` | 见 4.5 |

**性能预算分配 = 设计口径**：只有传说档与闪光色开动画，图鉴**列表缩略图一律静态**
（仍走既有的 `IntersectionObserver` 懒绘制），只有**详情页大图**开动画。
「稀有的东西才配动」既是性能分配，也是稀有度的表达。

> ⚠️ 侧视下，鱼的侧向摆动（z 方向）在屏幕上读感偏弱（是朝向 / 背离镜头的运动）。
> 所以另外叠了「尾鳍摆动 + 呼吸 + 轻微偏航」把「活着」这件事读出来。**这不是装饰，是必要的补偿。**

## 10. 实现回填：9 种体型的实际落地（2026-10-07，队列 T3）

> 代码：`src/render/fishmesh.js`　｜　可视验证台：`tools/style-preview-3d.html`（加载真模块，不是复制版）
> 本节的数字与结论都是**实测**，不是设计意图。设计意图在上面的 §3。

### 10.1 九种体型的实际做法

| 体型 | 生成方式 | 面数（普通 → 史诗 → 传说） | 关键特征 |
|---|---|---|---|
| fish 通用鱼形 | 车削式（环垂直 x） | 240 → 242 → 265 | 基准体型 |
| eel 鳗鱼 | 车削式，16 站细长 | 275 → 277 → 300 | 通体等粗 |
| shark 鲨鱼 | 车削式 + 拱背 | 240 → 242 → 265 | 高背鳍 + 新月尾 |
| **ray 鳐鱼** | **平面型驱动**（环沿 z 铺开） | 348 → 350 → 370 | **展向 1.48 > 体长 0.87**，厚仅 0.19 |
| squid 鱿鱼 | 车削式 + **立起来的**侧鳍 + 前伸触手 | 348 → 378 → 406 | 触手朝**前**，不是朝下 |
| jelly 水母 | **脊柱沿 y**（伞盖是绕 y 的回转体） | 434 → 462 → 490 | 伞盖 + 悬挂触手 |
| oarfish 皇带鱼 | 车削式，18 站 | 329 → 331 → 354 | 背冠做成**实心鳍** |
| whale 鲸鱼 | 车削式，体粗 | 286 → 288 → 308 | 尾叶是**水平**的（不是竖直） |
| dragon 龙鱼 | 车削式 + 棘刺阵 + 飘须 | 319 → 321 → 372 | 背棘 + 4 根须 |

### 10.2 稀有度 → 细节层级（用户口径：传说鱼要明显细节更足）

| 档 | detail | 加了什么 |
|---|---|---|
| 普通 / 稀有 | 0 | 基础剪影（体型 + 尾鳍 + 背鳍 + 胸鳍） |
| **史诗** | 1 | + 一对腹鳍；龙鱼棘刺；水母 / 鱿鱼 **+2 根触手** |
| **传说** | 2 | + **外沿飘带** + **双层尾鳍** + 棘刺加密加高 + 飘须 2 → 4 根 + 触手再 +4 根并拉长 |

**两条硬口径**（都写进了单测，不是口头约定）：

1. **细节必须改得动剪影** —— 缩到图鉴列表的 64px 时表面纹理全糊成一团，
   只有轮廓外的突起还读得出来。所以传说的额外结构是飘带 / 棘刺 / 双层尾鳍，
   不是「更密的网格」。单测直接断言：**传说档的包围盒必须变大**。
2. **每一档都要看得出来** —— 单测断言 `detail 1 面数 > detail 0 面数`（9 种体型全过）。
   ⚠️ 这条是被实际打回来的：水母一开始 detail 0 与 detail 1 都是 434 面，
   因为通用鳍逻辑对它不生效（`noFins`），**史诗档在水母身上完全不可见**。

**飘带的锚点按体型算，不写死**：鳐从翼尖、鲸从尾叶、常规鱼从尾鳍上下叶
（`streamAnchors()`）。挂在外沿才改得动剪影。

### 10.3 默认视角必须按体型给

| 体型 | 默认俯仰 | 为什么 |
|---|---|---|
| ray | **60° 俯视** | 侧视下鳐只是一条细缝，正面认不出 |
| jelly | -12° | 要看到伞盖内侧 |
| 其余 | 0°（侧视） | 侧视是辨识度最高的角度 |

⚠️ **这条我在重写模块时丢过一次** —— 旧参考实现里有 `defPitch`，新写的 `fishmesh.js`
第一版忘了带过来，结果鳐鱼又变回一条斜着的细缝。**规格里写了不等于代码里有**，
所以现在 `defaultView()` 是导出接口，单测直接断言「鳐的默认俯仰在 40°~80° 之间」。

### 10.4 本轮回填的两个坑

1. 🔴 **锚点漏字段 → 坐标变成 NaN → 什么都不显示，但不报错**
   鳐鱼的飘带锚点用了 `c.span`，而 `rayBody()` 返回的对象里没暴露 `span` →
   锚点算出 NaN → 整条飘带消失。**NaN 是最难查的一类 bug：它不抛异常、不白屏，
   只是少画一点东西**。现在单测对 **detail 2** 也断言「坐标全是有限数」。
2. 🔴 **方向错了，形态就全错** —— 触手一开始统一写成「朝下挂」（水母是对的），
   结果鱿鱼看着像两块薄片。改成按体型分：水母朝下、鱿鱼朝前伸。
   **别用一个方向套所有体型。**

| 帧率 | 52~54 fps（其中 9 格开动画） |

## 11. 实现回填：画质对齐 v9 参考图 + 颜色变异（2026-10-07，队列 T4）

> 用户口径：「生成鱼的风格和质量要有 v9 版本的样子」—— v9 是那批「强边缘光 + 暗底 + 黄金提亮」
> 的参考图（`D:/fish-style-samples/v9/`）。本节记录**为了让程序化输出长得像 v9 而改了什么**。
> 代码：`src/render/mesh3d.js`（光照）、`src/render/fishpaint.js`（新增，颜色变异）、
> 验证台 `tools/style-preview-3d.html`。

### 11.1 三处硬伤（出图才看出来，光看代码看不出来）

| # | 问题 | 症状 | 修法 |
|---|---|---|---|
| 1 | **固定 camZ = 3.0** | 长条鱼只占画面 24%，跟 v9 的满画面构图差很远 | 新增 `fitCamera()`：按包围盒在 **8 个朝向上取最坏值**算相机距离（取最坏值 → 旋转时不会「呼吸」）。主体占画面 78% |
| 2 | **光照区间太窄** | 亮度只在 0.62~0.85 之间变 → 整条鱼发白、**棱面全看不见** | 环境项 0.16→**0.10**、主光 0.85→**1.00**、腹部补光下限 0.62→**0.34**。亮度区间拉到 0.34~0.91 |
| 3 | **边缘光太散** | rimPow 2.0 把边缘光摊成一片晕光，v9 是**一条 crisp 的亮边** | rimPow 2.0→**3.0**，rimK 提到 1.05~1.55 |

> 🔴 **教训**：这三点都是「数字在合理范围内、代码也没报错、但画出来就是不对」。
> 第 2 条尤其典型 —— 我第一版为了「腹部不要黑」，把环境项和腹部补光一起调高，
> 结果**对比度被吃掉了**。修法是：**环境项压回去，只给朝下的面一个补光下限**
> （`bellyFloor`），让它不作用于亮面。

### 11.2 方向向量必须归一化

`LIGHT.key` 原来是 `[-0.32, 0.72, 0.42]`（长度 0.893）直接参与点乘 ——
**「光的强度」悄悄藏在了方向向量的长度里**，改方向就顺手改了亮度。
现在模块加载时统一归一化：方向归方向，强度只由 `keyGain` / `rimK` 控制。

### 11.3 颜色变异 → 材质参数（`fishpaint.js`）

每条鱼自带一对颜色（`fish.js` 的 `body` / `accent`）。变异**不是再画一张图**，
而是把这一对颜色按规则换算成材质参数：

| 档 | 手段 | 实现 |
|---|---|---|
| 原色 | 该鱼自己的配色对 | 深色当背、浅色当腹；**背腹明度差要拉开**，否则整条鱼糊成一片 |
| 亮色 | **同色系**提亮提饱和 | 色相 `h` 原样保留，只有 `s`/`l` 变化 —— 硬口径，单测盯着 |
| 白化 | **去色** | 色相几乎抹平（s→0.06），奶白体 + 粉鳍 |
| 黄金 | **换材质** | 金属金（`metallic: 1`），背深腹亮（金块更需要层次，否则成一块金饼） |
| 闪光 | **加光效** | 虹彩（`spin: 1` 让高光随时间扫过）+ 星点（`sparkle: 1`） |

**三档互不重叠**（单测断言）：白化去色、黄金换材质、闪光加光效 ——
退化成「同一个颜色深一点浅一点」就等于颜色变异系统白做了。

### 11.4 实测（`tools/style-preview-3d.html`，「真实鱼」视图）

| 指标 | 实测 |
|---|---|
| 出图条数 | 取样 **28 条真实鱼**（跨 7 个钓场、覆盖 4 个稀有度），各自用自己的配色 |
| 数据源 | `fish.js` 全部 **362 条**都能取到配色 |
| 帧率 | 61~101 fps（7 格开动画 = 传说档 + 闪光档） |
| 每帧重画 | 7 格（静态格零开销） |
| 控制台错误 | 0 |

对照图：`docs/images/v9对齐-体型-原色.png` / `v9对齐-真实鱼-原色.png` / `v9对齐-真实鱼-黄金.png`

### 11.5 与 v9 还差什么（如实记录）

- **v9 的面片更有机** —— 它的三角面大小不均、边缘有轻微的柔和过渡；
  我们的网格是规则环状分片，观感更「机械」。**这是程序化路线固有的差别**，
  不是 bug；要更像就得做非均匀三角化（排到后面按需做）。
- **v9 的高光是柔和的衰减**，我们的镜面是硬边幂次。低多边形下这个差别不明显。
- 鱼的整体明度还可以再亮一点（当前偏「沉沉的水下感」，v9 更「影棚」）。
  `[待调]` —— 这条要等放进真实场景一起看，单独看图容易调过头。

## 12. 实现回填：按 v9 参考图拟合体型比例（2026-10-07）

> 用户口径：「你现在画的鱼不行，能不能先把 v9 文件夹下的鱼 3D 建模给我看看」——
> 即**把 v9 那批参考图当建模目标**。
> 参考图已入库：`docs/images/v9-ref/`（6 种体型的原色版）
> 量测脚本：`tools/measure-silhouette.py`　｜　并排对比：`docs/images/v9对照-建模对比.png`

### 12.1 做法：先量，再拟合（不靠肉眼估）

`tools/measure-silhouette.py` 用同一套掩膜算法量**参考图**与**本模块的出图**，
输出包围盒宽高比 + 沿体长的 12 段宽度剖面。两个原因必须这么做：

1. 肉眼估比例不可靠 —— 我先按肉眼调过一版，量出来差了 40%
2. 量出来才知道**差在哪一项**（是身体太粗？还是鳍太小？还是尾巴太短？）

### 12.2 拟合结果（两轮）

| 体型 | v9 参考宽高比 | 拟合前 | 拟合后 |
|---|---|---|---|
| 通用鱼形 | 2.59 | 1.85 | **2.55** |
| 鲨鱼 | 3.29 | 2.22 | **3.03** |
| 鳐鱼 | 1.66 | 1.01 | **1.37** |
| 鱿鱼 | 2.35 | **5.78** | **2.61** |
| 水母 | 0.54 | 0.63 | 0.63 |
| 龙鱼 | 3.14 | 3.53 | **3.19** |

主要修的是三件事：**身体太短太粗**（普遍）、**鳐鱼展向太窄**、**鱿鱼细长得完全不像**。

### 12.3 顺带修好的两个口径问题（都是出图才发现的）

**① 稀有度不该藏「器官」。**
原来把腹鳍 / 臀鳍放在 detail ≥ 1，结果**基础档的鱼只有孤零零一个背鳍**，
跟 v9 的普通鱼（本来就有全套鱼鳍）完全不像。
改成：**基础档就给全解剖结构**（背 / 胸 / 腹 / 臀 / 尾鳍），
稀有度递进改成 —— **史诗 = 同样的鳍更长更飘（finScale 1.17）**、
**传说 = 再叠飘带 / 双层尾鳍 / 棘刺（1.34 + 装饰）**。

> 🔴 **由此暴露一个测试设计错误**：原来断言「detail 1 的面数 > detail 0 的面数」，
> 而「鳍变长」**不增加面数**，于是这一档在测试里完全隐形。
> 改成**按剪影验**（包围盒必须变大）—— 这才是「细节看得见」的正确判据。

**② 默认视角给错了角度。**
鳐鱼原来设 60° 俯仰 —— 那是**斜俯**，展向会被 cos 压扁（实测宽高比掉到 0.69）。
正确的俯视要接近 **88°**。角度差 28°，结果完全不同。

### 12.4 与 v9 还差什么（如实记录，不粉饰）

并排一看就清楚：**结构对了，完成度还不够。**

| 项 | 差距 |
|---|---|
| 鳍的体量 | v9 的背鳍 / 胸鳍 / 尾鳍都明显更大更舒展，我的偏小 |
| 身体饱满度 | v9 的躯干更"实"，我的仍偏瘦 |
| 鱿鱼 | 仍是最弱的一种：v9 是「长筒身 + 三角鳍 + 一束触手」，我的接近「胖纺锤 + 几根线」 |
| 鳐鱼 | 展向仍小于 v9，且缺头部凹口与翼尖后掠的细节 |
| 龙鱼 | v9 有背鳍、长须与扇形尾，我的只有棘刺与短须 |

**结论**：比例这一层已经对齐（可复现、可量测），**体量感与细节密度是下一轮的事**。
这不影响把渲染接进图鉴（T5）—— 结构对了就能用，装饰可以后加。
