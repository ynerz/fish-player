## 2. 后续开发流程（每轮怎么走）

**一句话**：看清工作区 → 按队列取**第一个可做**的条目 → 先量后改 → 门禁双绿 → 文档三处同步 → 两笔提交。

| 步 | 动作 | 硬要求 |
|---|---|---|
| ① 开工 | `git log -6` + `git status --short`；跑 `test.js` / `verify.js` | 工作区只许脏 `manifest.json`（常驻生图产物，**不碰不提交**）；**门禁红先修门禁** |
| ② 选条目 | `优化队列.md §1` 的「下一轮起点」优先，其次 §2 第一个可做 | 可做 = 未阻塞 **且** 不与在跑的进程冲突 **且** 不需要拍板 |
| ③ 先量后改 | 改之前先跑一次只读探针 / 真数据统计 | 本项目最贵的教训：判据与阈值必须**用真代码路径**量过（N2 砍掉两条判据、N3-1 量了 40 张卡面） |
| ④ 改 + 门禁 | `verify` 新增断言**必须先证明它会报红**；`test.js` 同步补断言 | **不许**为了让门禁变绿而放宽断言；跑门禁**不许接管道**（管道会吞退出码） |
| ⑤ 真浏览器 | 碰 UI / 素材 / 画面的改动：`python -m http.server` + `tools/browser-probe.js` | 单测全绿但画面是坏的，本项目真的发生过；**用完必须关服务** |
| ⑥ 收尾 | 规范 §6 的 7 步：反向陈述 / grep 常量 / 同步三处文档 / 门禁反向验证 / 记忆落盘 / 更新队列 / 一笔提交 | 一轮**最多 1 个 A 类**条目 |
| ⑦ 回写 | 待办标 `[x]` + **只追加**新发现；队列 §1 / §4 / §5 同步 | 发现**只追加、绝不改已有条目**；没新发现就跳过，不为了填而填 |

**插队规则**：用户报障 > 队列条目（历史上有过两次：评审台打不开、闪光档头身不一致）。
**踩坑速查**：改代码前先扫 `.workbuddy/memory/TRAPS.md`（静默失效 26 条 + 浏览器 / 出图细则）。

## 4. 关键路径与风险

1. 🔴 **生图批次是唯一的总闸门**：S1 / S2 全部卡在它身上。它不停，就只能做 S0。
   剩余 ≈ 12.9 机器小时 ⇒ **如果机器连续开机，10-10 当天能跑完**；断续跑则可能拖到 10-11。
   ⚠️ 判据永远是**看锁的心跳**（`assets/cards/.gen-art.lock`），不是看「我记得它在跑」。
2. 🔴 **4 项等拍板会各自卡住一整条支线**（Q23 / Q4 / Q5 / N4 / N5-4-5 / N2-L2）。
   历史口径：标注 ⛔ 的条目**整项跳过、不停等**，所以它们**不会拖慢其他阶段**，只会自己留在原地
   ⇒ 「S4 什么时候完成」完全取决于用户什么时候给口径。
3. ⚠️ **速率的真实上限是「机器开着 + 自动化真的每小时跑了一轮」**：
   10-09 的 11:00~17:30 段几乎没有提交 ⇒ 现实里按 **10~15 轮/天** 折算更稳。
4. ⚠️ **素材体积红线（2026-10-09 口径变更）**：主包 ≤ 4 MB / 总量 ≤ 30 MB（**这是小游戏的上限**）。
   `assets/cards/` 实测已 **1.5 GB**（2317 张 / 单张 ≈0.5MB）⇒ **卡面不可能随包分发**，
   必须走**远端按需拉取 + `manifest.json` 的 size 档**（小游戏吃低码率 / Steam 吃高清）。
   ⇒「**资源托管**」**不是可选项**，与「上不上服务端」是同一件事的两半（详见 `优化队列.md §3.3`）。
5. ⚠️ **语音能力的平台差异**：本地 `speechSynthesis` 在 Web 端可用（离线、无 Key），但**小程序端没有**、
   「没有用户手势不许出声」是浏览器策略 ⇒ N6 必须做成**可降级**（拿不到能力就退回纯文字气泡），
   并且**要把 `speechSynthesis` 加进 `verify` ㊱ 的禁字表**（否则它是「没上锁的门」，`performance.now` 当年就这么漏的）。
6. ⚠️ **NPC / 社交的形态由合规决定，不由技术决定**（2026-10-09 更正理由，结论未变）：
   原先写的是「**没有服务端** ⇒ NPC 只能是本地拟真角色」—— 服务端**现在已被放行**，
   但结论仍然成立、**理由换成了版号**：微信小游戏**含「用户生成内容 / 社交系统」等复杂功能被列为需要版号的情形**，
   而版号审批 6~12 个月且需企业主体。⇒ **不碰版号就只能做单机拟真**（NPC + 本机档案排行 + 分享卡）；
   文案里要**明确标注非真人**；事件奖励**只许纯外观**（纪念币 / 生态值 / 称号 / 装饰）。
7. ⚠️ **发现堆积**：34 条未做的「自动化发现」本身就是新债。
   建议做法：**每清掉 10 条**就复跑一次全量审计（规范 §3 的 C 类只读审计），
   并把「连着两轮都在做的同一类小修」合并成 1 个 A 类条目收口。
8. 🔴 **合规是新的关键路径**（2026-10-09 检索留档，非技术风险、但会决定产品形态）：
   微信小游戏**纯广告变现（免费）目前不需要版号**（需软著 + 工信部备案）；
   **含虚拟支付必须版号**（个人主体不能内购，必须迁企业主体）；**Steam 国际版不需要中国版号**，
   但 Steam 开国区 / **TapTap 国内需要版号**。⚠️ **「捕鱼」是平台强监管类目** ——
   本作是休闲钓鱼、不是街机捕鱼，但**类目申报时要避开「捕鱼」字样**。
