# A. 数值与平衡

## A1 ✅ `balance.js` 第 ② 节的收益表是错的（已修）

**证据**
- `tools/balance.js:68-71` `waitTime(rar)` **不接收 field 参数**，直接返回 `U.range(timeMin, timeMax)`
- 而真正该用的 `G.Loot.biteTime(rar, {field})`（`src/core/loot.js:72-84`）会乘上场地的 `biteMul`
- 同文件 `simulateCollect`（`balance.js:156`）却**正确传了** `{ field: field }` —— 一个文件里两套口径

**影响**：`biteMul` 是 B/A/S/SS/SSS 场「让后期自然变慢」的唯一手段，漏乘后这些场的「每小时竿数」被高估、收益被高估。

实测重算（已修正 biteMul）：

| 钓场 | 单竿耗时 | 竿/时 | 每小时金币（修正） | 旧报告值 | 虚高 |
|---|---|---|---|---|---|
| D | 47.5s | 76 | 2,150 | 1,776 | — |
| C | 48.4s | 74 | **2,078** | 1,542 | — |
| B | 64.2s | 56 | 3,777 | 3,272 | — |
| A | 96.5s | 37 | 6,448 | 5,744 | — |
| S | 114.9s | 31 | 7,589 | 8,062 | ×0.94 |
| SS | 110.8s | 32 | 10,766 | 14,811 | **×0.73** |
| SSS | 117.5s | 31 | **12,176** | 24,313 | **×0.50** |

**建议**：`waitTime(rar)` → `waitTime(rar, field)`，内部改调 `G.Loot.biteTime(rar, { field })`，与游戏本体共用一份实现。改完重跑并同步 GDD/说明书里的收益数字。

## A2 ✅ C 场收益倒挂（已修）

**证据**：`src/data/fish.js` 由 `tools/gen-fish.py` 生成，C 场鱼的 `price` 偏低；C 场 `biteMul = 1.0` 与 D 相同，单竿耗时也几乎一样（48.4s vs 47.5s），所以收益直接由鱼价决定 → 而 C 场平均鱼价 27.9 **低于** D 场 28.4。

**影响**：第二个钓场是「新手验证点」，收益倒退会直接劝退。

**建议**（按代价从低到高）
1. `gen-fish.py` 里给 C 场鱼价整体 ×1.35 左右，重生成后跑 `solve-drop.js` + `balance.js`
2. 或给 C 场 `biteMul` 降到 0.9（咬口更快）
3. 顺手把整条曲线拉平：目标「每进入一个新场，每小时收益至少 +40%」。当前 A→S 只有 +18%。

## A3 ✅ 装备价格梯度和场次进度不匹配（已重标定）

**证据**：`src/data/items.js`。用修正后的收入算「攒够钱要多久」：

| 装备 | 价格 | 在 A 场 | 在 S 场 | 在 SSS 场 |
|---|---|---|---|---|
| 碳素矶竿 | 5,200 | 0.8 h | 0.7 h | 0.4 h |
| 深海船竿 | 32,000 | 5.0 h | 4.2 h | 2.6 h |
| 传说·星陨竿 | 210,000 | **32.6 h** | 27.7 h | 17.2 h |

而玩家在 A 场要待 **44.7 小时**、S 场 **99.5 小时**。也就是说**每到一个新场，不到一半的时间就能把该场最贵的装备买下来**，装备没有「追逐感」。

装饰更极端：最贵的「小木船」只要 56,000（≈ 星陨竿的 1/4）。

**建议**：把竿/线价格整体上抬一个量级并与场次绑定（例如下一档装备 ≈ 新场 60~80% 的停留时长），装饰作为纯奢侈品再单独上一档（10 万级）。

## A4 ✅ 平衡数值散落在 config 之外（已收拢）

`config.js` 开头写着「这里是整个游戏唯一需要调数值的地方」，但：

# B. 玩法与系统缺口

## B1 ✅ 结算卡「收藏」是死按钮（已做鱼护 + 水族箱）

**证据**
- `index.html:134` 有 `<button id="ccKeep">收 藏</button>`
- `src/ui/panels.js:884` 每次结算都 `U.$('#ccKeep').classList.add('hidden')`
- `src/ui/panels.js:921` **只给 `#ccSell` 绑了事件**，`#ccKeep` 全项目零处理器
- 全项目搜索 `inventory / 背包 / bag` → **零结果**

也就是说：鱼一上钩就自动进图鉴 + 自动折现，玩家点不点那个按钮完全一样，只是被强制点一次。

**影响**：这是个以「收集」为长线目标（828 小时）的游戏，却不存在「我想要这条鱼，我先留着」的决策，收集的仪式感被削掉一半。

**建议**（三选一，建议方案 2）
1. 最轻：删掉 `ccKeep`，把结算卡改成「自动收下」的信息展示，别让玩家白点一次
2. **推荐**：加**鱼护/水族箱**。钓到的鱼进鱼护（有容量上限，可升级），玩家可以「放生 / 卖出 / 放进水族箱展示」；水族箱给被动收益或纯展示
3. 最重：做完整背包 + 市场行情波动

## B2 ✅ 挂机时打开面板会停掉钓鱼（已修）

**证据**：`src/main.js:214-226`
```js
var paused = P.isCatchOpen() || P.isOpen();
if (document.visibilityState === 'visible') St.tick(dt);
if (!paused) { F.update(dt); ... }
```
`paused` 把 `F.update` 一起停掉了。后果：挂机开着一去看图鉴，鱼就不咬了，而且 `St.tick` 还在累计游玩时长（时间在走、进度不走）。

**建议**：拆开两件事 —— `F.update` 只在**结算卡**打开时暂停（玩家要看渔获），浏览面板（图鉴/商店/统计）时挂机继续跑。若担心玩家错过渔获，播报栏已经能兜住。

## B3 ✅ 咬钩前的浮漂异动提示（已补）

**证据**：`src/core/fishing.js:183`
```js
if (waitLeft <= 8 && !pending._hinted) { pending._hinted = true; }
```
只置了个标记，**没有任何消费方**，`Scene` 也没有对应表现。

**建议**：`waitLeft <= 8` 时调 `G.Scene.floatNudge()`（浮漂轻晃 + 细波纹），并播一个音量很低的前置音。这是「提前收杆」这个操作唯一的价值来源。

## B4 ✅ 失败零代价（已加断线修理费）

**证据**：`config.js:86` `progLossOnFail: 0`；`fishing.js` 的失败分支只记统计（`snaps++` / `escapes++`），**不扣金币、不扣饵、不掉进度**。

**建议**：至少给「断线」加代价 —— 断线损失该竿的鱼饵 + 一个小额金币修理费（或鱼线有耐久，用金币修）。当前「断线」和「放弃」在收益上完全等价，玩家没有理由认真躲逃窜。

## B5 🟠 828 小时只有「图鉴」一个长线目标

**证据**：`grep -rn "achieve|成就|quest|daily|任务" src/` → **零结果**

**建议**：加三层目标
- 短（每次上线）：每日 3 个任务（钓 10 条、钓 1 条史诗、在某场用某饵钓 5 条）
- 中（每周）：限时鱼（某条鱼本周概率 ×5）、周常挑战
- 长（跨场）：成就系统（图鉴类 / 纪录类 / 操作类），给称号与纯装饰奖励

## B6 🟡 没有新手引导

首次进入只有 HUD，没有教「按住收线 / 松手放线 / 躲逃窜」。`index.html` 里也没有 `noscript`。

**建议**：第一次抛竿时用非阻塞气泡逐步提示三个动作，玩家完成即消失，可在设置里重看。

1. **`form` 是鱼类学术语，扩散模型读不懂，部分还会误导。**

2. **`form_profile()` 的提前 return 把 `body_ratio` 整条推导路径吃掉了。**
