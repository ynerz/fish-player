### 3.1 待拍板：结算卡弹出时，底栏怎么处置？（Q23）

结算卡（`.catch-card`）是**居中卡片**、不盖底栏，所以底栏在它弹出时仍然可点 ——
点槽位会开出面板，而结算卡 `z-index 60` 会浮在面板（`50`）上面，两层叠着。

**两种做法，观感差别明显，且属于产品取舍（不是 bug），所以不由自动化决定：**

| 方案 | 做法 | 代价 / 风险 |
|---|---|---|
| **A. 只禁用槽位** | 结算卡待决时给 `.deck-left`（三个槽位 + 挂机开关）加禁用态；`#btnAction` **保持可用** | 保留「点抛竿 = 收下」这个既有手感；但结算卡仍然不盖底栏，场景照常透出来 |
| **B. 结算卡加背景遮罩** | 给 `.catch-card` 加一层全屏半透明遮罩（与 `.modal` 同款），底栏自然被盖住 | 更一致（两个「要求独占交互」的层用同一套规则）；但**会改变「刚钓上鱼」那一刻的画面**（场景被压暗），审美上是个改动 |

⚠️ 无论选哪个，`#btnAction` 在结算卡待决时**点一下等于「收下」**是**故意**的
（`handlePress()` 里 `if (P.isCatchOpen()) { P.dismissCatch(catchDone); return; }`），
动它就会改手感 —— 所以它要不要一起禁用，是这件事里最需要你拿主意的一点。

## §4 本轮的自主决策留痕（规范 §9.2 要求）

| 决策 | 结论 | 为什么不选另一条路 |
|---|---|---|
| `requestAnimationFrame` / `cancelAnimationFrame` | **收进 `G.Platform.sys.raf` / `cancelRaf`**，并给「拿不到 raf」加 `setTimeout` 兜底（**补时间戳**） | 不收口的代价在平台迁移时兑现：小程序（非小游戏）页面**没有全局 raf**。顺带把 `panels.js` 里两处 `if (cancelAnimationFrame)` 能力守卫删掉 —— 能力在不在是平台层的事，业务侧只该守「我自己的状态」 |
| `setTimeout` / `setInterval` | **不收口**，业务代码直接用 | 任何宿主都有（Node 也有），包一层只是多一层无意义间接，而且会**掩盖**「真正要换的只有帧调度」这一个事实。收口一半不整齐，但整齐不是目标，**规则能被执行**才是 |
| 面板里新滑块的位置：放在「背景音乐」下面、**总音量上面** | 按待办建议的「背景音乐下面」放，并把总音量的说明从「整体音量 0 ~ 100」补成「（所有声音的总闸门）」 | 另一条路是「总音量在最上、各子音量在下」（层级更顺），但那会**挪动**玩家已经记住的五行的位置（音效 / 环境音 / 背景音乐 / 音量 / 挂机），为一个新滑块付这个代价不值。靠文案说明「相对总音量的比例」把关系讲清楚更省 |
| **环境音**要不要也加一条音量滑块 | **不加**（本轮只做音乐） | 环境音本来就被压到 `ambGain 0.10`（全场最轻的垫底声），而且已经有独立开关；再加一条滑块是**多一个旋钮给玩家做无意义的决定**。待办条目只点名音乐，按「一轮一个条目」也不该顺手扩面 |
